## 浏览器打不开时，按顺序检查

### 1. 证书是否在"受信任的根证书颁发机构"

```powershell
Get-ChildItem Cert:\LocalMachine\Root | Where-Object { $_.Subject -match "Caddy" }
```
应看到 `CN=Caddy Local Authority - 2026 ECC Root`。
没有就重新导入（管理员）：
```powershell
certutil -addstore -f ROOT "C:\Users\xuee\Desktop\肥鱼之心\deploy\caddy\caddy-root.crt"
```

### 2. 完全关闭浏览器再开

Chrome/Edge 会缓存证书错误状态，必须**完全退出**（包括后台进程）再打开。

```powershell
Get-Process msedge,chrome -ErrorAction SilentlyContinue | Stop-Process -Force
```

### 3. 代理是否拦截

clash 系统代理（127.0.0.1:7897）可能拦截 `itsaplan.lan`。
在 clash 里把 `*.lan` 或 `172.20.10.0/28` 加入直连/bypass 规则。

测试是否被代理拦截：
```powershell
curl.exe --noproxy "*" --ssl-no-revoke https://itsaplan.lan/login   # 绕过代理
```

### 4. 用这个命令判断是服务端还是客户端问题

```powershell
# 能 200 说明服务端好，问题在浏览器/证书信任
curl.exe --noproxy "*" --ssl-no-revoke -k https://itsaplan.lan/login
# 不加 -k 报 CRYPT_E_NO_REVOCATION_CHECK 是 Windows 命令行工具的严格检查
# 浏览器不会这么严格
curl.exe --noproxy "*" https://itsaplan.lan/login
```

## 已知：命令行 curl 会报吊销检查错误

```
schannel: CRYPT_E_NO_REVOCATION_CHECK (0x80092012)
```

**这是 Windows curl（schannel）对自签证书的严格行为**，因为 Caddy 的本地 CA 没有提供 OCSP/CRL 吊销服务地址。
**浏览器（Edge/Chrome）不执行这个检查**，所以浏览器能正常打开。

命令行调试时加 `--ssl-no-revoke` 即可绕过。

## 为什么必须用域名不能用裸 IP

Windows schannel 不支持对纯 IP 发 SNI：
```
curl: schannel: using IP address, SNI is not supported by OS.
```
Caddy 无法按 host 匹配证书 → TLS alert 80。
所以 hosts 里必须有 `itsaplan.lan`。

## IP 变化时

1. 主机上查新 IP：
```powershell
Get-NetIPConfiguration -InterfaceAlias WLAN | Select-Object -ExpandProperty IPv4Address
```
2. 改本机 hosts 那一行
3. 重新生成配置：
```powershell
python proto\set_lan_ip.py <新IP>
cd deploy\caddy; docker compose restart
```
