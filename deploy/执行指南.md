## 3. 恢复数据（从迁移备份）

### 3.1 解包备份
把 `proto\archive\迁移备份_20261120.zip` 解压到临时目录，里面有：
- `itsaplan-db-backup/itsaplan_full_20261119_093036.sql`
- `itsaplan-attachments/`（20 个附件文件）

### 3.2 导入数据库（顺序很重要）
```powershell
# ★ 正确顺序（已核实 migrate.ts 逻辑）：
#   migrate 服务启动时会先建表 + 自动备份。所以必须先让 stack 完整跑一次，
#   等 migrate 建表完成，再停服务、导 dump、重启。
#   否则 dump 和 migrate 建的表会冲突。

# 1. 等 migrate 跑完（它是一次性服务，跑完状态为 Exited 0）
docker compose -f docker-compose.yml -f docker-compose.override.yml ps
#    看到 itsaplan-migrate-1 状态 Exited (0) 即可

# 2. 停掉会读写数据库的服务（postgres 保留运行）
docker compose -f docker-compose.yml -f docker-compose.override.yml stop api worker bot

# 3. 清空 migrate 刚建的空库，再导入 dump（--clean 会先 DROP 再 CREATE）
type itsaplan_full_20261119_093036.sql | docker compose exec -T postgres psql -U itsaplan -d itsaplan

# 4. 重启服务
docker compose -f docker-compose.yml -f docker-compose.override.yml start api worker bot
```

✅ **已核实**：这份 dump（备份 `迁移备份_20261120.zip` 内）是 `pg_dump 17.12` 生成，
自带 `DROP TABLE ... IF EXISTS` 语句，导入时会自动先删旧表再建，**不需要手动清库**。

⚠ 注意 dump 开头有 `\restrict` 指令（pg_dump 17 新增），
必须用 **psql 17** 导入 —— itsaplan 的 postgres 容器就是 `postgres:17-alpine`，
容器内的 psql 版本匹配，所以上面的 `docker compose exec postgres psql` 方式正好可用。
不要用 Windows 本地装的旧版 psql 导入，会报 `\restrict` 无法识别。

## 5. 常见问题

**Q：网页打不开？**
1. `curl http://172.20.10.100` 看 Caddy 是否返回
2. 检查 clash 是否把 172.20.x 走了代理 → clash 里 bypass `172.20.0.0/16`
3. 检查 Windows 防火墙 mirrored 放行命令是否执行过

**Q：登录成功但马上退出？**
`NODE_ENV` 不是 development，cookie 带了 Secure 但走 HTTP。
确认 `.env` 里 `NODE_ENV=development`。

**源码级依据**（`packages/auth/src/index.ts`，已核实）：
```js
const hostPrefixedCookies = baseURL.startsWith('https://') && !cookieDomain;
secure: hostPrefixedCookies || process.env.NODE_ENV === 'production',
```
- 我们：`http://` + `development` → secure=false ✓ cookie 正常
- 若改成 `production` 但仍 HTTP → secure=true → 浏览器丢弃 cookie → 登录循环
- 若改成 HTTPS（真证书或自签被信任）→ hostPrefixedCookies=true → `__Host-` 前缀 cookie，此时应把 NODE_ENV 改回 production

另外源码 `parentDomain()` 对 IP 返回 undefined，`sameHost`（web/api 同主机）时
cookieDomain 也是 undefined → 我们用 IP + `/api` 路径形式，走 host-only cookie，正确。

**Q：docker pull 失败？**
Docker Desktop → Settings → Resources → Proxies → Containers proxy 选 System proxy，
或填 `http://127.0.0.1:7897`，Bypass 填内网段。

**Q：数据没恢复？**
检查 `.env` 里的 `APP_ENCRYPTION_KEY` 是否和备份一致（不一致则已存凭据解不开）。

## 6. 日常运维

```powershell
# 启动全部
cd deploy\caddy; docker compose up -d
cd ..\itsaplan; docker compose -f docker-compose.yml -f docker-compose.override.yml up -d

# 停止全部（数据不丢，在 volumes 里）
docker compose down

# 更新 itsaplan
cd deploy\itsaplan
docker compose pull
docker compose -f docker-compose.yml -f docker-compose.override.yml up -d

# 备份数据库
docker compose exec postgres pg_dump -U itsaplan itsaplan > backup.sql
```
