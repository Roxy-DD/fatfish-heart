## 三、核心结论（重要）

**我们 73.8% ≈ Letta 74.0%（不做记忆工具，纯文件系统）。**

这说明：**LoCoMo 这类 benchmark 的上限主要由"回答模型强弱"主导，而非"检索机制多精巧"。**

我们做的检索优化（+30pp 召回），在最终答案质量上，和"简单文件系统"打平。

## 四、真实的差距在哪

1. **不是检索架构**：bi-encoder+cross-encoder+LLM精排+改写，业界有的我们都有，且验证过
2. **是 answer model 强弱**：业界 91 分用 GPT-4o 级作答，我们子代理默认模型可能弱
3. **是判等口径 + prompt**：LLM-as-judge 的 prompt 调优影响数 pp
4. **是 benchmark 性质**：LoCoMo/LongMemEval 是"事实检索"导向，天然偏向"事实仓库"路线，**测不出我们的差异化（情景/情绪/代价/模型自主）**

## 五、诚实结论

- **检索架构**：无代差，同一赛道
- **benchmark 数字**：73.8 vs 91+，差 17pp，大头在 answer model 和口径，不在记忆系统核心
- **真正差异化**（情景记忆哲学）：这些 benchmark 测不出来，是另一个维度的价值

## 六、要补的（如果要数字好看）

1. 换强 answer model（GPT-4o 级）做作答，而非子代理默认模型
2. 精调判等 prompt
3. 但这些都不是"记忆系统"的改进，是"评测配置"的改进
