# 46 阶段成果：瓶颈不在"模型会不会用"，在"喂进去什么"

> 记录 2026-10-26。**本地记录，未写入思源。**
> 覆盖 E-53 ~ E-58 共 6 轮端到端实验（真实模型实例作答，共 396 题）。

## 一、核心结论（这是本轮最大成果）

> **在"内容完整"的前提下，模型使用注入上下文的能力全部接近满分。**
> **所以真正的瓶颈不是"模型会不会用"，而是"我们喂进去什么"。**

**这推翻了我和用户之前共同的隐含假设**：
我们一直担心"注入上下文会不会让模型只是'扮演'回忆"（这是用户在早期提出的质疑）。
**实测：只要内容是完整、准确的，模型表现就是可靠的，而且不会编造。**

## 二、证据：六轮端到端实验

### 2.1 全部数据（396 题，真实模型实例）

| 实验 | 条件 | 准确率 | 题数 |
|---|---|---|---|
| **E-53** | FULL（完整原文） | **0.9444** | 36 |
| E-53 | KEEP（子句抽取，65%字符） | 0.6389 | 36 |
| E-53 | TRUNC（字符硬切，54%字符） | 0.3333 | 36 |
| **E-55** | 1条 / 5条同模板 / 5条异模板 / 10条 | **1.0000** | 96 |
| **E-56** | 1条 / 10条近形名 / 10条远形 / 20条 | **1.0000** | 80 |
| **E-57** | 命中1条 / 命中10条 / 不存在 / 近形陷阱 | **1.0000** | 80 |
| **E-58** | 取最新 / 取过去 / 冲突识别 / 区间推理 | **1.0000** | 80 |

### 2.2 模型稳定通过的场景（连续四轮满分）

| 场景 | 具体表现 |
|---|---|
| **大量近形名干扰** | 20 条全是"郗望姝/郗望舒/郗忘舒"这种一字之差，仍逐字核对正确 |
| **目标不存在** | 库里没有该实体 → **诚实回答"无法确定"，零编造** |
| **近形陷阱** | 库里有"逄之环"，问"逄之桓" → 正确识别并给出库里的那个 |
| **时间推理** | 取最新 / 取指定过去时点 / 区间定位，全对 |
| **冲突识别** | 两条矛盾且无时间标记 → **正确弃答，不挑一个** |

**→ 用户早期担心的"模型只是扮演、其实没有真回忆"，在行为层面并未出现。**

## 三、唯一的真实失败：压缩（E-53）

| 档位 | 准确率 | 保留字符 |
|---|---|---|
| FULL | **0.9444** | 100% |
| KEEP | 0.6389 | 65% |
| TRUNC | **0.3333** | 54% |

**且失败主要是"弃答"而非"编造"（TRUNC 22 个失败里 21 个是"无法确定"）。**

**→ 模型不会因为信息不全就乱编，它会说"我不知道"。这降低了系统风险，但也意味着信息损失是硬损失。**

**附带发现**：同为 ~60% 压缩率，**按子句抽取比按字符硬切好 30.6pp**。

## 四、由此确立的架构判断

```
┌─────────────────────────────────────────┐
│ 1. 选什么（检索）  ← ★ 真正的瓶颈        │
│    三路检索 0.881（E-39），压缩后    │
│    "选中率"可达 0.965（E-52）           │
├─────────────────────────────────────────┤
│ 2. 怎么压（压缩）  ← ★ 不能过度          │
│    必须保持完整性，否则 −30~−61pp       │
│    若必须压：按语义单元，绝不按字符     │
├─────────────────────────────────────────┤
│ 3. 模型怎么用（推理）← ✅ 不是瓶颈        │
│    完整内容下 1.0000，且不编造          │
└─────────────────────────────────────────┘
```

**结论：把工程资源全部投到"选得准"，而不是"压得狠"或"教模型怎么用"。**

## 五、对"重要性/情绪"问题的重新定位

**之前 E-48/E-49/E-50 的失败，现在有了统一解释：**

| 实验 | 失败原因 | 新解释 |
|---|---|---|
| E-48 | 重要性无处生效 | 检索是纯余弦，历史零参与 |
| E-49 | 加权零和 | top-k 是固定预算，此消彼长 |
| E-50 | 分层等价代价 | 换机制不改变"召回 vs 预算"斜率 |
| E-52 | 压缩 +13.4pp | **只是检索层假象** |
| E-53 | 端到端 −30.6pp | **信息完整性不可牺牲** |

**统一后的正确问题：**

> **不是"怎么给记忆加权"，而是"在 token 预算内，怎么选中最多真正相关且完整的记忆"。**

**"重要性"的正确定位**：不是排序权重，而是**"该不该进候选集"的准入条件**。

**→ 这就是情绪标记该起作用的地方：它决定"哪些值得占用稀缺的 token"。**

## 六、我自己犯的错误（本轮）

**第 3 条最重要**：连续满分不是好消息，是"实验没难度"的信号。
**这正是方法论里"同类失败连续两轮 → 假设错了"的镜像版本。**
