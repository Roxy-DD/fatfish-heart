## 一、七条实测缺陷

### A. 加噪阻碍合并（与主张相反）

**代码位置**：`cosmos_net.py` `RightHemisphere.dream()` 1.5 Noise Injection 段

**机制**：`dream()` 的顺序是 **先加噪 → 再按固定阈值合并**。
L2 归一化向量加噪后，期望内积 ≈ `c / (1 + D·σ²)`，D=784。

**实测**（300 次平均）：

| σ | 实测 cos | 理论 c/(1+Dσ²) | 仍 > 0.90 |
|---|---|---|---|
| 0.00 | 0.9962 | 0.9900 | 是 |
| 0.05 | **0.3377** | 0.3345 | 否 |
| 0.10 | 0.1092 | 0.1120 | 否 |
| 0.20 | 0.0327 | 0.0306 | 否 |
| 0.30 | 0.0178 | 0.0138 | 否 |

**20 个随机种子 × 5 档噪声**（T=0.90，初始 600 星）：

```
噪声σ    平均剩余星   总合并数
0.00      15.8        11683     ← 不加噪时合并发生
0.05      600.0       0         ← 加噪后一颗都合不了
0.10      600.0       0
0.20      600.0       0
0.30      600.0       0
```

**判定**：σ=0.05 就把余弦从 0.996 打到 0.34，远低于任何合并阈值。
**加噪不是促成合并，是彻底阻断合并。**

### B. 修剪规则删除刚学的概念

**代码位置**：`cosmos_net.py dream()`

```python
if start_count > 50:
    self.galaxy = [s for s in self.galaxy if s.mass > 1]
```

**机制**：`mass == 1` = 只见过一次 = **刚学的**。持续学习里，分数提升之前学的恰恰都是 mass==1。

**实测**：

```
任务 A 学完：3 颗星，mass 全 1
星数 3 <= 50 → 不修剪 → A 保住
任务 B/C 学完：63 颗星（>50）
做梦后：剩余 0 颗，A 类 0/3
```

**判定**：**任务 A 被完全删除。** 这不是「<0.1% 遗忘」，是 100%。

### C. SE/CD 数值与注释差 100 倍

**代码位置**：`analysis.py` `calculate_system_entropy` / `calculate_conflict_degree`

**实测**：

| | 代码实际算出 | analysis.py 注释声称 | README 声称 |
|---|---|---|---|
| SE | 6.3969 | ≈6.4 | −82% |
| CD | **0.1585** | **≈15** | −99% |
| CD/SE | **0.0248** | **≈2.3** | — |

**复现的 dream 后变化**：SE **−79.5%**、CD **−77.3%**。

**判定**：
- SE 量级对得上，CD 差 **100 倍**
- CD 降幅也与 README 对不上
- 注释与实现不一致，说明注释是手写的期望值，不是跑出来的

### D. Tolerance Law 的 k=0.34 是事后拟合

**代码位置**：`analysis.py find_optimal_k()`

```python
calc_threshold = k        # 直接扫阈值，CD/SE 根本没进计算
```

最后的 `k = best_k / ratio` 用的是**注释里的 2.3**，不是实际算出的 0.0248。

**用真实比值反推**：

| T | 剩余星数 | 反推 k = T/(CD/SE) |
|---|---|---|
| 0.80 | 3 | 32.29 |
| 0.85 | 3 | 34.31 |
| 0.90 | 9 | 36.33 |
| 0.95 | 600 | 38.35 |
| 0.99 | 600 | 39.96 |

**判定**：真实 k 是 **32–40**，不是 0.34。这条"定律"是先有结论再补公式。

### F. 默认路径下左脑是死的

**代码位置**：`cosmos_net.py LeftHemisphere._extract_features()`

```python
is_pixel_data = (len(vector) == 784)
```

**维度检查**：

```
Retina/MobileNetV2  dim=1280  is_pixel_data=False → 永久返回 (None, 0.0)
旧像素路径           dim=784   is_pixel_data=True  → 工作
```

**后果链**：
1. `knowledge_base` 永远空
2. `perceive()` 恒返回 `(None, 0.0)`
3. `CorpusCallosum.memorize()` 中 `l_correct` 恒为 False
4. `dominance` **只升不降，或停在 0.5**

**判定**：**v10.1 的主打卖点「双院制动态平衡」，在默认配置下不可观测。**
只有当不装 torch、回退到 784 像素路径时，左脑才活着。

---

### G. 特征在归一化后信息量极低

**代码位置**：同上 `_extract_features()`

**实测**：`density = sum(|v|)`，v 已 L2 归一化，若有 N 个等幅非零项则 `density ≈ sqrt(N)`

| 非零像素 n | 实测 density | 理论 sqrt(n) |
|---|---|---|
| 20 | 4.1230 | 4.47 |
| 50 | 6.5362 | 7.07 |
| 100 | 9.2462 | 10.00 |
| 200 | 13.1203 | 14.14 |
| 400 | 18.7937 | 20.00 |
| 784 | 26.0586 | 28.00 |

**判定**：`density` 只反映"墨迹多少"，与数字类别几乎无关——0/1/7 都能很瘦，8/9 都能很粗。
即使维度判断修好，左脑的判别力也很弱。

## 三、记忆载体问题（与"记忆迁移"目标直接相关）

| 记忆以什么形式存在 | 代码事实 | 对迁移的含义 |
|---|---|---|
| `cosmos_brain.pkl` | `save_brain()` pickle 整个 Python 对象 | 绑死在类定义上，代码一改就读不出来 |
| 迁移兼容层 | `CosmosUnpickler.find_class()` + 手动 `__class__` 重绑 | **仓库里已存在这个补丁**，说明 v9→v10 时确实崩过 |
| 记忆单元内容 | vector(1280) + label + mass + creation_time | 没有文本、没有语义锚点 |
| 可移植性 | 只对同一份 `cosmos_net.py` 有效 | 搬不到另一个模型，也搬不到语言模型 |

**一句话**：它的记忆是「一个 Python 对象的序列化快照」，不是「一份可以被另一个模型读懂的陈述」。

这恰好与本人《记忆的锚点与回溯性幻觉》的结论相反——那篇说真值源必须放在外部、可复查；而 `pkl` 恰恰是不可复查的黑盒。
