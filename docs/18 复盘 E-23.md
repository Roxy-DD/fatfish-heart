## 二、三个发现

### 2.1 HOG 用 128 维超过 784 维原始像素

```
hog128   128 维   macro 0.9380
raw784   784 维   macro 0.9183
                 → +1.97pp，维度 1/6.1
```

**为什么**：HOG 提取的是**梯度方向直方图**——它描述的是**笔画往哪个方向走**，而不是**像素在第几行第几列**。

这正是手写数字需要的信息。**原始像素把"形状"和"位置"绑在一起，HOG 把"形状"单独拿出来。**

**印证了搜索到的规律**：HOG 是 1986 年专门为行人/形状检测发明的，**它就是为这类任务设计的**。我绕了 12 轮才用上它。

### 2.2 拼接（pixel+hog）最好，但增益主要在 B/C

```
pixel+hog  0.9395  vs  hog128  0.9380   → 只高 0.15pp
```

**几乎没差别。** 说明 HOG 已经把 pixel 有的信息都涵盖了，**加回 pixel 基本是冗余。**

→ **应该选 hog128（128 维），不是 pixel+hog（912 维）。**
**维度 7 倍，性能一样。存储成本差 7 倍。**

### 2.3 「间隔大」不等于「效果好」——这条推翻了我的一个隐含假设

| 特征 | 间隔 | macro |
|---|---|---|
| pca64 | **0.2804**（最大） | 0.9165 |
| pca128 | 0.2591 | 0.9135 |
| center784 | 0.2434 | 0.9091 |
| hog128 | 0.1914 | **0.9380** |
| pixel+hog | 0.1659 | **0.9395** |
| raw784 | **0.1405**（最小） | 0.9183 |

**间隔最大的 pca64 反而 macro 中等；间隔较小的 hog128 却是最好的。**

**结论**：**"类间可分性"（间隔）不是唯一决定因素。特征是否"对准了任务的本质结构"更重要。**

pca64 的间隔大，但它压缩掉的是**形状细节**；HOG 的间隔小一点，但它保留的正是**形状**。

**这直接对应你的方法论**：
> "逻辑是拟合现实规律后的惯性，它不一定正确"

「间隔大 → 分得好」就是这种**逻辑惯性**。**实测把它推翻了。**

## 三、还有个意外：pca64 只有 64 维就接近 raw784

```
pca64    64 维   0.9165
raw784  784 维   0.9183
```

**12 倍压缩，性能几乎不掉。**

说明**原始像素里 90% 的维度是冗余的**（MNIST 大量像素恒为黑）。

**存储启示**：如果部署，pca64 可以把每颗星从 784 字节 压到 64 字节（float32 下 3 KB → 256 B）。

## 四、当前最好的配置

```
特征：HOG 128 维（cells=4, bins=8）
阈值：0.560（HOG 空间标定）
检索：平坦 + 类内 top-3
macro：0.9380（3 seeds，12000 训练 / 4000 测试）
星数：1216
```

**对比参照**：
- 同特征最佳常规方法（LogReg，语义空间）：0.8360
- 起点（原实现，语义特征 + 层级）：0.6767（A）
- 语义特征 + 11 轮优化：0.8831
