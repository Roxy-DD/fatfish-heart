## 一、三步法

```
1. 抽象类比
   把技术问题 → 抽象成现实生活中会遇到的具体问题

2. 搜索规律
   去搜这些问题在各行各业、现实生活中，大家是怎么解决的
   去了解真实的现象、规律、数据是什么

3. 迁移套用
   从这些信息里发现规律 → 迁移、套用到当前问题
```

---

## 二、核心逻辑（原话）

> **"规律只在一个地方出现，就是现实生活。
> 别的各行各业，都只是通过各自的视角，去记录他们所看到的东西。"**

> **"你无法直接看到现实，但你可以通过搜索非常多的行业或视角，
> 去还原这个世界尽可能真实的数据，从而得到尽可能真实的规律。
> 这就是你处理无法解决的问题时，一个思考的方向以及方法论。"**

**推论**：
- 单一学科的结论是**某个视角的投影**，不是规律本身
- **多行业交叉印证**才接近规律
- 一个视角说不通，换视角再问

## 三、配套的另外两条（同样重要）

### 3.1 不预设门槛

> 用户原话（2026-10-25）：
> **"这种实验的东西不应该预设门槛，而是遇到了什么问题，
> 看什么会造成效果变差或者变好，然后不断地去确定边界，不断地完善修改就行了。"**

**翻译成实验规则：**

| 不写 | 改写成 |
|---|---|
| "macro 必须 > 0.90" | "什么让它变好？什么让它变差？边界在哪？" |
| "这个方案要成功" | "这个假设成立/不成立，各需要什么证据？" |

**为什么**：预设门槛会诱导"凑数"，甚至把**作弊上限**当目标。
（我犯过：拿 oracle 的 0.9520 当目标，追了两轮空。）

### 3.2 逻辑是拟合，不是真理

> 用户原话（2026-10-25）：
> **"在现实世界里，逻辑不可靠，只有现实规律才是绝对的真实。
> 自然界出现的东西，那就是真的。
> 你任何的逻辑规律之类的东西，其实都是拟合出现实规律后的一种逻辑惯性，它不一定就是正确的。"**

> **"真正正确的数据，就是你直接获取到的自然界的真实数据。
> 而且有可能你获取的途径就会出现问题，
> 所以你并不能绝对保证你的数据是绝对正确的，逻辑也是绝对正确的。
> 因此，你不能让它不变，它必须是一直变的，必须是一个流动的、过程性的。"**

**两条操作含义：**

| 含义 | 具体做法 |
|---|---|
| **数据获取途径本身可能错** | 换途径验证（换特征、换数据集、换随机种子） |
| **任何常数都不能冻结** | 阈值必须由当前数据实时决定，不能离线算死 |

### 3.3 输入只是接口

> 用户原话（2026-10-25）：
> **"即使你是盲人，也可以考试；即使你摸不了盲文，光听也能考试。
> 所以，它只是一整套逻辑而已，
> 前置的这种数据处理、信息录入只是一种方式。"**

**含义**：特征/输入只是接口，**换接口比优化逻辑可能更有效**。
（实证：换特征后 0.8831 → 0.9441，什么都没改。）

## 三．五、文献只是借势，不是权威（最高优先级）

> 用户原话（2026-10-25）：
> **"这套方法论你现在能查到的，也不一定是正确的。
> 永远记得我说的观点：最主要的是，永远正确的只有现实规律。
> 比如说，现实中它只要能出现，我只要跑出结果了，那它就是真。
> 即使现在行业已经怎么做，那我只要能跑出更好的结果，
> 或者能跑出更好的东西出来，那它就是对的。
> 也就是使用别人的结论只是一种借势，
> 但是不认可别人的一定正确，永远抱有绝对的怀疑，
> 只相信现实世界的真实规律。"**

### 三层优先级（从高到低）

```
1. 我自己跑出来的结果        ← 最高。跑出来就是真
2. 现实世界能观察到的现象    ← 高。只要能出现就是真
3. 行业/文献/权威的结论      ← 最低。只是借势，不是真理
```

### 具体操作规则

| 场景 | 规则 |
|---|---|
| 搜到一条规律 | **只当"候选假设"，不当"答案"** |
| 文献说 A 好 | **必须自己跑一遍验证**；若我的结果与文献冲突，**信我的结果** |
| 文献给了公式/参数（如"±3σ"） | **只借它的"思路"，参数从我的数据里重新推** |
| 我的结果更好 | **以我的为准**，文献只是"已知的另一种做法" |
| 我的结果与文献一致 | 只说明"这个视角在我这里也成立"，**不构成"文献对"的证明** |

### 为什么必须这样

**文献是"别人在别人的条件下看到的投影"**，不是规律本身。
即使那是个正确的规律，**换到我这个条件也未必成立**（E-24 就是活例子：记忆科学三条规律在我这里全部不成立）。

**真正的检验标准只有一个：跑出来。**

### 由此推出的做法变更

| 旧做法 | 新做法 |
|---|---|
| 搜到规律 → 直接实现 | 搜到规律 → **提炼出"该测什么变量" → 从数据里自己定参数** |
| 用文献的默认参数 | **参数一律从当前数据标定**（这本来就是"不冻结常数"） |
| 文献与结果不符 → 怀疑自己 | **文献与结果不符 → 记录，以结果为准，并说明分歧** |

## 四、这条方法论救过我什么（实证）

| 我卡住的问题 | 抽象成现实问题 | 搜到的规律 | 结果 |
|---|---|---|---|
| 忘什么、怎么判重要性 | 档案管理员怎么销毁文件 | **按类别定保留期，不逐个打分** | 找到死结的解法 |
| 重复能否加强记忆 | 人怎么把事记牢 | **提取→窗口内重学；0 间隔无效** | 修正了我的理解 |
| 权重单向饱和 | 怎么防一人独大 | **轮值反对者 / 任期制 / anti-windup** | 找到机制 |
| 阈值冻结 | 边界怎么随环境流动 | **感官适应 / 慢时间常数积分反馈** | 找到机制 |
| 特征选不对 | （用户直接点破） | — | 0.8831 → 0.9441 |

## 五、我自己的执行规则（配合上面）

| 规则 | 来历 |
|---|---|
| **改动前先做量级审计**（打印参数实际取值范围） | 犯过 2 次：density、evt_beta |
| **对照必须样本量/星数匹配** | 犯过：E-13 ceiling、E-19 percentile |
| **不得用作弊上限做目标**（oracle、单任务训练） | 犯过 3 次 |
| **单种子不作结论** | 犯过：E-9 |
| **"恒真条件"必须在跑之前查出来** | 犯过：E-14 margin 空操作 |
| **同类失败连续两轮 → 是假设错了，不是方法不够** | 自己总结 |
| **文献结论未经验证就当假设，不当答案** | 用户 2026-10-25 明确要求 |
| **迁移前先问"它作用的对象和我的一样吗"** | 犯过：E-24（情景记忆 vs 语义归类） |

## 六、一句话

> **遇到解不动的技术问题，别继续调参。
> 先把它翻译成现实生活里的问题，
> 再去多个行业/视角搜大家怎么解决的，
> 把规律搬回来。**
>
> **因为规律只在现实生活里出现，各行业只是各自的视角。**
