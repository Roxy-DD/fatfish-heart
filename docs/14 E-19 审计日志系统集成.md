## E-19 审计日志系统设计

### 设计目标

- **问题**：调试靠猜，不知道注入/回忆/睡眠何时发生
- **解决**：结构化审计日志，每条操作可追溯
- **红线**：独立 audit_log 表，不碰主线 data（红线上游不变）

### 实现

```sql
CREATE TABLE audit_log (
    seq INTEGER PRIMARY KEY AUTOINCREMENT,
    at REAL NOT NULL,      -- 时间戳
    kind TEXT NOT NULL,    -- inject|recall|remember|sleep|conflict|...
    sid TEXT,              -- 会话 id
    ep_id TEXT,            -- 相关记忆 id
    msg TEXT,              -- 一句话描述
    extra TEXT             -- JSON 附加信息
)
```

### 埋点位置

| 模块 | 触发条件 | kind |
|---|---|---|
| cmd_add | 写入成功 | remember |
| cmd_search | 检索调用 | recall |
| cmd_sleep_apply | 睡眠整理 | sleep |
| cmd_judgeConflict | 矛盾判定 | conflict |
| cmd_expand | 链式展开 | chain |
| cmd_affect | 情绪判断 | affect |
| 配置变更 | 运行时改配置 | config |
| 异常 | try/catch | error/warn |

### UI 展示

新增「审计日志」Tab，提供：
- 时间线视图（精确到秒）
- 类型过滤（一键看某类事件）
- 总览统计（各类别累计）

**验收标准**：能看到最近的操作流水，能快速定位问题源头。

## E-20 ~ E-21 睡眠整理机制

### 设计目标

**核心洞察**：人有睡眠机制——白天经历的事晚上整理巩固。记忆系统也应有"任务完结时的整理"。

### 机制设计

```
白天（实时）：
  复盘 → 判断该记什么 → mem_add
  回忆 → 记不清时查 mem_search

节点（模型主动触发）：
  睡眠 → 整理碎片 + 回忆强化 + 遗忘过时 → mem_sleep
```

### 三动作

| 动作 | 含义 | 红线 |
|---|---|---|
| 整理 | 相似碎片 merge → 完整记忆 | drop 打 superseded_by，不删 |
| 遗忘 | 过时内容 invalidate | invalid_at 标记，不物理删 |
| 强化 | 本阶段关键记忆 bump channel | 只增不减 |

### 触发方式

**模型主动触发**（不是定时）：
```
"当一个任务/项目告一段落、一轮密集对话结束，你觉得'该整理了'，主动调 mem_sleep。"
```

### 实现

内核命令：
- `cmd_sleep_prepare` - 找候选对（系统机械做）
- `cmd_sleep_apply` - 模型判后再落盘
- `cmd_audit` - 读审计日志

UI Tab：「睡眠历史」

### 验收标准

- 模型能在合适的时机主动调用 mem_sleep
- 能正确合并碎片记忆
- 能正确标记过时内容
- 审计日志有完整流水

### 修正 E-22 的两个测试缺陷
