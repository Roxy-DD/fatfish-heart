# 65 cross-encoder 落地：最终结论（实测推翻假设）

> 建立 2026-11-07，更新至最终结论。**本地记录，未写入思源。**

---

## 一、最终结论（E-200 实测）

**在本机 CPU 环境下，cross-encoder 不能替代 LLM 精排。**

| 方案 | 命中率 | 延迟/题 |
|---|---|---|
| **LLM 精排（批量）** | **79.1%** | **~800ms** |
| cross-encoder（int8 ONNX，CPU） | 77.9% | **5712ms（慢 7 倍）** |

**结论：cross-encoder 既不更快（慢 7 倍），也不更准（-1.2pp）。**

---

## 二、为什么推翻"cross-encoder 快 6 倍"的假设

调研时看到的 130ms 是 **GPU/优化推理环境**下的单对打分。
本机是 CPU 无 GPU，onnxruntime 逐对前向：
- 244 题 × 50 候选 = 12200 次前向
- 平均 5712ms/题

**而 LLM 精排是"批量"（一次看 50 条，1 次调用），天然并行，反而更快。**

---

## 三、分题型对比（各有优劣，非一边倒）

| 类别 | LLM | cross-encoder |
|---|---|---|
| 时间（2） | 75.8% | **87.9%** |
| 对抗（5） | 60.0% | **85.0%** |
| 常识（4） | **93.5%** | 85.2% |
| 单跳（1） | **73.6%** | 58.5% |
| 多跳（3） | 40.0% | 40.0% |

cross-encoder 在时间/对抗类更优，LLM 在常识/单跳更优。**理论上可做"双精排融合"，但成本高，暂不做。**

---

## 四、最终方案（保留 LLM 精排）

```
向量检索 top-50（~90ms）
    ↓
LLM 批量精排（一次看 50 条，~800ms，命中 79.1%）
    ↓
取 top-10
```

**全量收益：+9.74pp（0.5802 → 0.6776）。**
