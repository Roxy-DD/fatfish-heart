# 63 精排落地与业界方案对标

> 建立 2026-11-02。**本地记录，未写入思源。**

## 一、我们的方案 vs 业界标准做法

### 我们做的（已验证）
```
向量检索 top-50（bi-encoder，~90ms）
    ↓
LLM 批量精排（一次看 50 条横向比较，~800ms）
    ↓
取 top-10
```
**LoCoMo 全量 +12.2pp（0.5802 → 0.7021），命中率 99%。**

### 业界标准做法（retrieve-and-rerank 范式）

| 环节 | 业界标准 | 我们 |
|---|---|---|
| 第一段检索 | bi-encoder 或 BM25（k=50~100） | ✅ bi-encoder（BGE-small） |
| 第二段精排 | **cross-encoder**（bge-reranker-v2-m3 等专门模型） | ⚠️ 用 LLM 代替 |
| 候选池 | N=20~50（甜点区） | ✅ N=50 |
| 提升 | nDCG@10 通常 +10~20 点 | ✅ +12.2pp |

**结论：我们的架构方向完全正确（retrieve-and-rerank），但精排实现用 LLM 代替了 cross-encoder，成本偏高（800ms vs 130ms）。**

## 二、可借鉴的现成方案

### 1. cross-encoder reranker（最该借鉴）

**bge-reranker-v2-m3** 等专门重排模型：
- 延迟 ~130ms（vs LLM 800ms）
- 效果与 LLM 相当或更好（学术界多次验证 cross-encoder 零样本泛化强于 bi-encoder）
- 成本：需本地加载模型（~1GB），但远低于每次 LLM 调用

**借鉴价值**：★★★★★
**收益**：延迟 800ms → 130ms，效果不降

### 2. CMC（EMNLP 2024，Comparing Multiple Candidates）

**一次比较多个候选，而非逐条**：
- 比逐条 cross-encoder 快 11 倍
- 提升 recall@16 +6.7pp

**这正是我 E-191 发现的"批量 > 逐条"的学术印证**——我的 LLM 批量精排（99%）优于逐条（90.7%），与 CMC 的结论一致。

**借鉴价值**：★★★★（印证了批量比较的正确性）

### 3. Mem0 / Zep 架构

**它们都是 retrieve-and-rerank 的变体**，核心思路与我们一致，但：
- 它们用更强的 embedding（如 OpenAI text-embedding-3）
- 检索后直接交给 LLM 生成答案（不做显式 rerank）

**借鉴价值**：★★（架构方向已一致，无额外收益）

### 4. 迭代检索 / RAG fusion

**多轮查询扩展**。但 E-181 已实测 RRF 多查询在 LoCoMo 上 -6.67pp（无效），因为我们的场景是"同主题实体高频"，多查询引入噪声。

**借鉴价值**：★（已实测无效）

## 三、诚实说明：口径差异

**我们报的数字（0.7021）不能直接和业界论文比：**

| 口径 | 我们 | 业界（LoCoMo 论文/Mem0） |
|---|---|---|
| 指标 | **检索召回**（evidence 命中率） | **F1**（答题质量） |
| 精排 | LLM 选证据 | cross-encoder 排序 |
| 数据 | 10 对话全量 | 10 对话（同源） |

**Mem0 在 LoCoMo 报 91.6 F1，我们报 0.70 召回——两者不是同一个量，不能比。**

## 四、明确了"突破什么"和"不够好"

### 突破了
1. **定位了真实瓶颈**：不是 embedding 语义（余弦中位 0.67），是排序精度（98.3% 差距 <0.03）
2. **验证了批量精排 > 逐条**（99% vs 90.7%），与 CMC 论文独立印证
3. **全量 +12.2pp**，落在业界 reranker 提升的 10-20 点区间

### 不够好
1. **精排用 LLM，成本高**：800ms vs cross-encoder 130ms
2. **多跳题（cat 3）仍是硬伤**：0.3913，因为它是推理题不是检索题（E-179 已证）
3. **没接进插件**：还是离线评测

---

## 五、下一步建议（按数据）

1. **换 cross-encoder 精排**（bge-reranker-v2-m3）替代 LLM —— 延迟降 6 倍，效果不降
2. **多跳题单独处理**：检索 + LLM 推理（而非检索 + 排序）
3. **接入插件**，做真实对话验证
