## 二、我的设计错误（必须作废 ceiling）

### 2.1 错误是什么

**`ceiling` 用了 900 样本/类 × 10 类 = 9000 条训练数据。**

而 `incremental` 每任务 900 条：A 覆盖 3 类 → 约 300/类；C 覆盖 4 类 → 约 225/类。
**incremental 总共只有 2700 条。**

所以 ceiling 的样本量是 incremental 的 **3.3 倍**。

### 2.2 为什么 3.3 倍数据反而更差

结果：`ceiling 0.8402 < incremental 0.8831`。

**天花板低于实际值，这是逻辑矛盾。**

原因推断：在这个系统里，**数据越多 → 星数越多 → 类间候选越多 → 干扰越严重**。
星数从 1428（incremental）涨到约 4000+（ceiling），密度效应压过了数据量的收益。

### 2.3 正确的 ceiling 该怎么定义

**"内在可分性上限"必须与 incremental 的样本量对齐**，否则测的是"数据量效应"，不是"任务难度"。

正确做法：
- 每类训练样本数 = incremental 中该类的平均样本数（≈250–300）
- 总计 ≈2700 条
- 10 类同时训练，测试时 unrestricted

**或者更干净的替代**：用 `within_only` 作为上限估计——它就是"只学这一个任务"的表现，不含任何跨任务干扰。

## 三、有效结论（这一条很强，不受 ceiling 错误影响）

### 3.1 `oracle` ≈ `within_only`，且都 ≈ 0.95

```
within_only  macro = 0.9538
oracle       macro = 0.9520
差 0.0018 —— 在噪声内
```

**这意味着：增量学习本身几乎没有损失。**

当你把候选限制在"正确任务的标签"内时，A→B→C 顺序学完后的表现，和"只学这一个任务"**完全一样**。

### 3.2 全部损失 = 跨任务标签竞争

| 任务 | within/oracle | incremental | **跨任务干扰** |
|---|---|---|---|
| A | 0.984 | 0.904 | **8.00pp** |
| B | 0.932 | 0.901 | **3.00pp** |
| C | 0.945 | 0.845 | **9.67pp** |
| macro | 0.9520 | 0.8831 | **6.89pp** |

**这是本轮最重要的发现：**

> **类内学习能力是 0.95 级的，但被跨任务标签竞争吃掉了 6.89pp。**
>
> **瓶颈不是"学不会"，是"认错任务"。**

### 3.3 这推翻了 E-12 复盘里的一个推断

E-12 复盘时我判断：「C 的困难来自类间混淆（内在难度）」。
E-13 显示：**C 的 oracle 是 0.9413**，几乎和 A/B 一样好。

→ **C 本身不难。** 作为第一个任务只有 0.8560，是因为**其它任务还没学**时星少、密度低；
而学完之后 unrestricted 预测时，被 A/B 的类抢走。
**它难的是"在 10 个标签里选对"，不是"在 6/7/8/9 里选对"。**

**这是对上一轮复盘结论的修正，必须记下来。**

## 四、把错误的那一列剔掉后的净分解

| 项 | A | B | C | macro |
|---|---|---|---|---|
| **类内上限**（within_only） | 0.984 | 0.932 | 0.945 | 0.9538 |
| **跨任务干扰**（上限 − 增量） | **8.00pp** | **3.00pp** | **9.67pp** | **6.89pp** |
| 剩余（增量 1-acc） | 9.6pp | 9.9pp | 15.5pp | — |

**跨任务干扰解释了增量缺口的 45.6%（6.89 / 15.1）。**

剩余部分才是"每个任务自身的学习损失"，且与任务特性相关（C 的 9.67pp 干扰最大）。

## 五、方法论教训

| 教训 | 依据 | 严重度 |
|---|---|---|
| **对照组必须控制样本量** | ceiling 用 3.3 倍数据，结果低于实际值，逻辑矛盾 | **严重，导致整列作废** |
| **天花板低于实际 = 设计错误的强信号** | 我一开始没警觉，是需要训练的直觉 | 中 |
| **oracle 是合法诊断工具** | 它作弊（知道任务标签），但只用于归因，不用于部署 | 无 |
| **`within_only` 是比 ceiling 更干净的上限** | 它有相同的样本量、零跨任务污染 | 好做法 |

## 六、下一轮（E-14）设计

### 6.1 问题

> **能否在不使用 oracle 的前提下，把 6.89pp 的跨任务干扰拿回来？**

当前 0.8831 macro，oracle 上限 0.9520。**中间有 6.89pp 可捡。**

### 6.2 已经失败的方法（不再重试）

| 方法 | 为什么失败 | 教训 |
|---|---|---|
| `prior_norm`（log 先验）beta=0.1+ | 惩罚大类摧毁大类本身 | beta 量级 |
| `evt_beta`（sqrt(2log n) 校正） | 校正项 0.9 >> 信号 0.05 | **量级未检查** |
| `zscore` | 跨类尺度不可比 | 需要候选筛选+统一尺度 |

### 6.3 新方法（按理论合理性排序）

| # | 方法 | 原理 | 预估 |
|---|---|---|---|
| **1** | **margin 拒答/降权** | 若 top1 与 top2 差距 < δ，把 top1 降权或看 top-k 一致性 | 中 |
| **2** | **按类内分布标准化余弦** | 每类的 cos 减去该类自身均值/除以标准差，使跨类可比 | 高 |
| **3** | **competition（抑制）** | 每类得分减去"被其它类抢走的历史比例" | 中 |
| **4** | **保底配额** | 星少的类在打分时获得固定加成（不是 log，是常数或 √n 的温和版） | 中 |
| **5** | **两级检索：先判任务、再判类** | 用任务层面的原型做门控（不是 oracle，是学习出来的） | 高，但要额外训练 |

### 6.4 判据

| 项 | 判据 |
|---|---|
| 主判据 | macro > 0.90 且 A_min > 0.88（5 seeds） |
| 干扰回收率 | (新 macro − 0.8831) / 6.89 > 50% |
| 不得回退 | C 不得低于 0.845 |

### 6.5 特别注意

方法 2 和方法 4 都可能重蹈"量级错误"。
**规则：任何加减项，先打印它在样本上的实际取值范围，再决定系数。** 这写进流程。
