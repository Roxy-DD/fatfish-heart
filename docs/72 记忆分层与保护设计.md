## 三、分层设计(五层保护等级)

不是"钩子 vs 非钩子",而是按**不可丢失程度**分五层:

| 层级 | 名称 | 定义 | 保护行为 | 举例 |
|---|---|---|---|---|
| **L0** | 不可变 | 红线、底线。动了就是错 | **永不失效/永不合并/永不修订** | R1 迁移100%、R2 不遗忘 |
| **L1** | 常驻准则 | 每次对话都必须生效的指令 | **永不失效**，且每次注入必带 | "以实验数据为准"、"自主决策" |
| **L2** | 设计基石 | 定义了系统是什么的核心洞察 | **不可失效**，但可被更好的表述取代 | "记忆单位=情景"、"重要性=代价" |
| **L3** | 阶段性事实 | 会随项目进展变化 | 可失效(打标记)，可 merge | "项目当前状态(截至E-105)" |
| **L4** | 一次性细节 | 测试数据、临时记录 | 可清理 | "密码8848" |

## 四、每层的具体保护规则

### L0 不可变(红线)

```
不可失效 ✗
不可合并 ✗
不可修订 ✗   ← 连 revise 都不允许
```

**理由**: 红线是"动了就是错"的约束。连修订都可能引入偏差。

### L1 常驻准则(行为指令)

```
不可失效 ✗
不可合并 ✗
可修订 ✓（表述可以更清楚，但不能改语义）
每次注入必带 ✓  ← 与 L0 相同的"永远在场"
```

**理由**: 这些是"告诉模型该怎么做"的指令，缺了模型行为就变。
但表述可以优化(比如更简洁)，所以允许 revise。

### L2 设计基石(核心洞察)

```
不可失效 ✗
不可合并 ✗
可修订 ✓（可以被更准确的表述取代）
不强制每次在场（按需检索）
```

**理由**: 这些定义了"这个系统是什么"，丢了就失去了设计依据。
但不需要每次对话都注入，检索到即可。

### L3 阶段性事实

```
可失效 ✓（打标记，不删）
可合并 ✓
```

**理由**: 会随进展变化，如"项目状态截至E-105"已被更新的取代。

### L4 一次性细节

```
可清理 ✓
```

**理由**: 测试数据、临时记录，无长期价值。

## 五、实现方案

### 5.1 存储(守 R1: 不加表，用 meta)

```python
key = "hook:<ep_id>"
value = {"level": "L0"|"L1"|"L2", "kind": "...", "note": "...", "at": ...}
```

**为什么不加列**: 
- 改 episodes schema → schema_version 变 → R1 迁移风险
- meta 是 key-value，加前缀不影响现有数据

### 5.2 保护检查点

| 位置 | L0 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| `invalidate()` | ✗拒绝 | ✗拒绝 | ✗拒绝 | ✓ | ✓ |
| `supersede()` | ✗拒绝 | ✗拒绝 | ✗拒绝 | ✓ | ✓ |
| `revise()` | ✗拒绝 | ✓ | ✓ | ✓ | ✓ |
| `consolidate` merge drop | ✗跳过 | ✗跳过 | ✗跳过 | ✓ | ✓ |
| `consolidate` invalidate | ✗跳过 | ✗跳过 | ✗跳过 | ✓ | ✓ |
| `search` 追加 | ✓强制 | ✓强制 | ✗ | ✗ | ✗ |

### 5.3 内核命令

```
hook action=list                    列出全部受保护记忆
hook action=lock ep_id=X level=L1   锁定
hook action=unlock ep_id=X          解锁（L0 需二次确认）
hook action=check ep_id=X           查询层级
```

### 5.4 插件层

- 新增 `mem_hook` 工具(模型可自查/申请锁定)
- UI 记忆列表里用不同颜色边框标识 L0/L1/L2

## 八、实现结果（2026-11-07 完成）

### 8.1 代码模块

**新增 `proto/cosmos_mem/hook.py`**（约 240 行）：
```python
LEVELS = {
    "L0": {no_invalidate:True, no_merge:True, no_revise:True,  always_present:True},
    "L1": {no_invalidate:True, no_merge:True, no_revise:False, always_present:True},
    "L2": {no_invalidate:True, no_merge:True, no_revise:False, always_present:False},
    "L3": {全 False},
    "L4": {全 False},
}
```
API：`level_of` / `can_invalidate` / `can_merge` / `can_revise` / `always_present` / `lock` / `unlock` / `protected_of` / `present_ids` / `stats`

**保护接入点**：

| 位置 | 修改 |
|---|---|
| `store_v1.invalidate()` | 调 `can_invalidate`，L0/L1/L2 拒绝 |
| `store_v1.revise()` | 调 `can_revise`，L0 拒绝 |
| `store_v1.supersede()` | 调 `can_invalidate`，L0/L1/L2 拒绝 |
| `store_v1.search()` | 调 `present_ids`，L0/L1 强制追加（flag=2） |
| `consolidate.apply_sleep_verdict()` | merge/invalidate 都跳过 L0/L1/L2，记入 `skipped_hooks` |

**内核命令**：`hook` action = `list` / `check` / `lock` / `unlock` / `levels`

**插件层**：
- HTTP 端点 `/hook`（GET 列保护 / POST 改保护）
