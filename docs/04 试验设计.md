# 04 试验设计

> 建立 2026-10-25。
> **目的：按真实设计意图（`01 设计意图` 的七步链条）重做一个可验收的原型。**
> 不复刻 README 的主张，只实现代码里真实存在的设计决策，并修掉 `03 缺陷与证据` 的 A–F。

---

## 一、验收判据（先定，后跑）

**每条判据都必须能被证伪。写不出阈值的，不进这张表。**

| 编号 | 检验什么 | 观测量 | 阈值 | 判定方式 |
|---|---|---|---|---|
| **E-1** | 增量学习不遗忘 | 学完 3 个任务后，任务 1 的测试集准确率 | **> 90%** | 与「学完任务 1 时」的准确率对比 |
| **E-2** | 阈值是有效旋钮 | 5 档阈值下的「碎片率 / 混淆度」曲线 | 存在**单调可分辨**的转折点 | 星数与 CD 同向变化 |
| **E-3** | 压缩真的降熵 | 做梦前后 SE、CD | SE 降 **> 50%**，CD 降 **> 30%** | 同批数据前后对比 |
| **E-4** | 记忆可迁移 | 导出/重载后，同一输入的预测**一致率** | **100%** | A 实例导出，全新 B 实例重载，逐条比对 |
| **E-5** | 双估计器不退化 | dominance 的双向变化次数 | **两个方向都 > 0** | 记录 1000 次学习后的 dominance 轨迹 |
| **E-6** | 遗忘规则不误杀 | 任务 1 的星在压缩后存活率 | **100%**（mission-critical） | 构造"新鲜但弱"的对照组 |

**E-4 是核心。** 它是"记忆迁移"唯一的硬判据：**同一个记忆，换个进程能不能一致地重建行为。**

## 二、与原实现的关键差异

| 项 | 原实现 | 本原型 | 理由 |
|---|---|---|---|
| 加噪 | 合并前加噪（阻断合并） | **合并后**加噪，或对阈值随机化 | 修缺陷 A |
| 修剪 | `mass > 1` | **新鲜度 + 质量双阈值** | 修缺陷 B |
| CD 分母 | 簇心欧氏距离 | **角度距离**（1 − cos） | 修缺陷 C |
| 左脑维度 | `len == 784` | **784/1280 双支持**，1280 走投影特征 | 修缺陷 D |
| 合并范围 | 同标签 | **允许跨标签**（可配置） | 修缺陷 E |
| 递归合并 | 不递归 | **递归到 children** | 修缺陷 F |
| 存储 | pickle 整个对象 | **JSON + numpy 数组，schema 版本化** | 支撑 E-4 迁移判据 |

**存储这一条是新增的，原实现没有。** 原因：pickle 绑死类定义，无法满足 E-4。

## 三、实验矩阵

```
                    特征：MobileNetV2 (1280d, 冻结)
                              │
              ┌───────────────┴───────────────┐
              │                               │
      E-1 增量学习                     E-2 阈值扫描
      3 任务顺序学                     T ∈ {0.75,0.80,0.85,0.90,0.95}
              │                               │
              └───────────────┬───────────────┘
                              │
                      E-3 压缩（做梦）
                              │
              ┌───────────────┴───────────────┐
              │                               │
      E-4 迁移导出/重载               E-5 双估计器轨迹
      (JSON, 新进程)                  (dominance 时间序列)
                              │
                      E-6 修剪误杀对照
```

**数据**：MNIST，已下载在 `proto/data/`（11 MB）。
**切分**：任务 A = 数字 0,1,2；任务 B = 3,4,5；任务 C = 6,7,8,9。
**每任务**：训练 3000 / 测试 1000（CPU 可承受）。

## 四、单次运行预算（实测）

| 项 | 数值 |
|---|---|
| 数据下载 | 11 MB（已完成） |
| MobileNetV2 权重 | 约 14 MB |
| 特征提取 | 12000 张 × 1280d，CPU 约 2–5 分钟 |
| 学习与评测 | 秒级（numpy 点积） |
| 内存峰值 | < 500 MB（特征矩阵 12000×1280 float32 ≈ 61 MB） |
| 磁盘 | < 100 MB |

**全程无需 GPU、无需云端。** 特征只算一次，落盘为 `.npy`，后续实验全部读缓存。

## 六、不做的事

| 不做 | 理由 |
|---|---|
| 不做 UI | 与判据无关，会引入"看起来做好了"的错觉 |
| 不做 3D 星图 | 可视化不能替代数字 |
| 不写"辩证"相关 | 与机制无推导关系 |
| 不主张"零遗忘" | 只有 E-1 通过才能说，且只能说"本设置下" |
| 不追求 SOTA | 目标是验证机制，不是刷 MNIST 准确率 |

## 七、失败时的处理（预先写下）

| 若 | 则 |
|---|---|
| E-1 未过 90% | 记录实际数；先查是不是阈值太低导致概念混淆，再决定是否调 |
| E-2 找不到转折点 | 说明阈值不是有效旋钮，**V-3 判定不成立** |
| E-3 SE 不降 | 说明压缩无效，dream() 需要重设计 |
| **E-4 未达 100%** | **迁移机制不成立**，这是本试验最重要的失败可能 |
| E-5 dominance 单向 | 双估计器未真正工作 |
| E-6 有误杀 | 修剪规则需再改 |

**预先写下失败处理，是为了防止跑完再找理由解释。** 这是试验设计的一部分，不是保险。
