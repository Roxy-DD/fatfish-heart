## 二、逐项细节

### A. int8 量化 BGE 向量

```
原始（float32）: 39.1 MB
int8 量化后:      9.8 MB
压缩比:           4.00×
top5 重叠率:      98.40%（对全精度基准）
检索延迟:         1.24 → 1.14 ms（略快，因为数据量小）
```

**判读**：
- **召回损失 1.6%**，在可接受范围（阈值 95%，实测 98.4%）
- **存储省 4 倍**
- **检索速度略快**（int8 数据量小，缓存友好）

**关键设计（守住 I-5 特征无关性）：**
量化参数 `lo` / `scale` **一起存入**，所以能**无损还原**近似向量。
原始文本仍然保留在真值层 → 换 embedding 模型时可重算。
**这就是"量化只是加速层，不是真值"的正确做法。**

### B. FTS5 倒排

```
numpy 全表扫描: 1.175 ms（2 万条）
FTS5 倒排:      0.204 ms
加速:           5.8×
```

**判读**：这是**结构性提升**——numpy 是 O(N)，FTS5 是 O(log N)。
**规模越大，差距越大。** 10 万条时 numpy 6.21ms，FTS5 应该仍在 0.2–0.5ms。

### C. 编码缓存

```
冷（真编码）: 8.22 ms/次
热（命中）:   0.0012 ms/次
加速:         6785×
```

**判读**：**收益巨大，但有个前提**——查询内容必须**完全重复**。
真实对话里问法不会完全一样，所以命中率是关键。

**必须诚实说明：6785× 是理论上限，实际命中率取决于使用场景。**
同一批记忆被反复问同一件事时（比如"我的参数是什么"），命中率会很高。

## 三、红线复验（这是本轮最重要的部分）

| 红线 | 检查项 | 结果 |
|---|---|---|
| **I-1 记忆与模型解耦** | 存储是否为纯数据（无代码/模型依赖） | ✅ int8 + 量化参数 + 文本，全是数据 |
| **I-2 迁移 100%** | 重载后矩阵是否完全一致 | ✅ **完全一致（True）** |
| **I-2 迁移 100%** | 逐条预测一致率 | ✅ **100.0%** |
| **I-2 迁移 100%** | 最大偏差 | ✅ **0.00e+00** |
| **I-3 分配不覆盖** | 本轮未改写入逻辑 | ✅ |
| **I-4 不遗忘** | 重载后条数 | ✅ **20000 / 20000** |
| **I-5 特征无关** | 原始文本是否保留 | ✅ 保留在真值层 |
| **召回未退化** | top5 重叠 ≥95% | ✅ **98.4%** |

**关键：量化后重载，最大偏差是 0.00e+00（完全零误差）。**

**为什么能做到零误差**：量化是确定性的（同样的 lo/scale 和 int8 值，反量化必然得到同样的 float）。
**而且反量化后的向量存的是 float32，所以"再次保存"也是确定的。**

**→ 量化不破坏无损迁移。这是本轮最重要的验证。**

## 四、组合后的效果（估算）

原方案（E-40，10 万条）：
```
编码 6.41 ms + V检索 8.58 ms + K检索 6.21 ms ≈ 21.24 ms
存储 195 MB
```

优化后（同样 10 万条，估算）：
```
编码 6.41 ms（缓存命中时 ≈ 0）
V检索 ≈ 2-3 ms（int8 数据量小）
K检索 ≈ 0.2-0.5 ms（FTS5）
合计 ≈ 9 ms（缓存未命中）/ ≈ 3 ms（缓存命中）
存储 ≈ 49 MB
```

**延迟降低约 2–7 倍，存储降低 4 倍。**

**注：这是估算，V 检索的 int8 大规模表现还没实测（规模小看不出差异）。**
