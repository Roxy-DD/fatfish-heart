# 34 实验基准：不可回退的创新

> 建立 2026-10-25。**本地记录，未写入思源。**
> 用户明确要求：**保留已实现的新创新，在此基础上探索性能优化。**
> 本文件是"红线清单"——任何优化如果破坏了下面任一条，即为失败，不算进步。

---

## 一、不可回退的 5 条创新（实测通过）

| # | 创新 | 实测证据 | 破坏判据 |
|---|---|---|---|
| **I-1** | **记忆与模型解耦**：纯数据存储（向量+计数+schema 版本），不含代码/模型 | **8000/8000 = 100%**，余弦偏差 **0.0**（E-4） | 换进程后预测不一致，或需要原始代码才能加载 |
| **I-2** | **跨进程无损迁移**：独立子进程重载，逐条复现 | E-4 已验证 | 迁移后出现任何不一致 |
| **I-3** | **分配而非覆盖**：新知识新建单元，不改写旧单元 | E-1 结构验证 | 旧记忆被新学习改写 |
| **I-4** | **不遗忘**：数据全量保留，准确率随数据单调上升 | E-29：1k→32k，0.904→0.964 | 因优化导致准确率下降或旧数据丢失 |
| **I-5** | **特征无关性**：换特征只需重标阈值，记忆本身不用重建 | E-22/E-23：HOG/像素/语义各自标定阈值即工作 | 换特征必须重建记忆库 |

## 二、性能优化的允许范围

**可以改（不影响上表）：**

| 允许 | 说明 |
|---|---|
| 加索引结构 | FTS5 倒排、HNSW、IVF —— 索引可从真值层重建 |
| 量化压缩 | int8 / PQ —— 真值层保留全精度或原始文本，量化只是加速层 |
| 缓存 | 编码缓存、查询缓存 —— 缓存可丢弃 |
| 并行/批量 | 编码批量化、分块计算 |
| 换检索算法 | 只要**召回不降**且**迁移仍 100%** |

**不可以改：**

| 禁止 | 理由 |
|---|---|
| 把记忆存成不可移植格式（如 pickle 对象） | 破坏 I-1/I-2 |
| 为了省空间丢弃原始文本 | 破坏 I-5（换 embedding 要重算，需要原文） |
| 引入"覆盖式更新" | 破坏 I-3 |
| 主动剪枝换性能 | 破坏 I-4（除非用户明确要求省存储） |

## 三、每个实验必须报告的四项

```
1. 性能指标（延迟/存储/召回）
2. ★ 无损迁移复验（迁移一致率必须 100%）
3. ★ 召回未退化（对比前一版）
4. 结论：这次优化是否触碰红线
```

**第 2、3 项是硬性要求。任一不达标，该优化作废，不再讨论。**

## 四、当前基线（优化起点）

| 项 | 当前值 | 出处 |
|---|---|---|
| 召回（五类查询，路由组合） | **0.881** | E-39 |
| 单路最好（V_bge） | 0.732 | E-39 |
| 查询延迟（1万条） | 7.24 ms | E-40 |
| 查询延迟（10万条） | 21.24 ms | E-40 |
| 写入吞吐 | 468 条/秒 | E-40 |
| 10万条 BGE 向量 | 195 MB | E-40 |
| 迁移一致率 | **100%** | E-4 |

**优化目标：在保持 0.881 召回和 100% 迁移的前提下，把延迟和存储降下来。**

## 五、允许的优化方向（按预期收益排序）

| # | 方向 | 预期 | 风险 |
|---|---|---|---|
| **P0** | **FTS5 倒排替换 numpy 全表扫描** | K 检索 O(N)→O(log N)，10万条 6.21ms→<1ms | 低（SQLite 内置） |
