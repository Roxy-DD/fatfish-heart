## 一、情绪 = 重要性的索引（文献证据）

### 1.1 核心机制：杏仁核是"闸门"，不是"放大器"

| 来源 | 关键原句 |
|---|---|
| Hermans 2014（Neurobiology of Learning and Memory） | 杏仁核在情绪唤醒时参与 **"gating"**（闸门），**决定哪一组表征会被重新激活**，"基于 salience 和 valence 计算，选择行为上重要的序列，决定哪些信息被优先巩固" |
| Richter-Levin 实验室 | 提出 **"Emotional Tagging"（情绪标记）** 概念：杏仁核激活**作为一种情绪标签**，增强其他脑区（海马、前额叶）的记忆巩固 |
| McGaugh 2015（Annual Review） | "这套情绪唤醒激活的神经生物学系统，**让我们的记忆强度反映其情绪重要性**"（the strength of our memories will reflect their emotional significance） |

**→ 这直接支持用户的判断：重要性是"以情绪为索引"的，因为杏仁核是闸门/标签，不是加分器。**

### 1.2 最关键的发现：情绪可以"追溯性"标记

| 实验 | 结果 |
|---|---|
| Nielson & Powless 2007 | 读完中性词表后，**最多 30 分钟后**看喜剧或手术视频 → **一周后对这些中性词的记忆改善** |
| Dunsmoor 2015 | 看中性图片（动物/工具）时给**轻微电击** → **改善对同类（同类别）图片的记忆** |

**→ 情绪标记不需要在编码时发生，可以事后补打；而且会按"类别"扩散。**

**这一条对我们极重要**：意味着"重要"可以**事后计算并回填**，不需要在写入时就知道。

### 1.3 但要诚实：情绪效应是"复杂且可变的"

Richter-Levin 原文：

> "情绪对记忆的效应是**复杂且可变的**（complicated and variable）……唤醒水平、效价、被试性别都会影响。
> 而且情绪刺激与非情绪刺激还可能在其他维度上不同（如**新奇性**、**关联性**），这些差异本身也影响记忆。"

**→ 不能简单假设"情绪强 = 记得牢"，必须实测。**

## 二、Mem0 的实现（2026-04 新算法，README 明示）

### 2.1 五项关键改动

| # | 改动 | 对应我们 |
|---|---|---|
| **1** | **Single-pass ADD-only extraction**：一次 LLM 调用，**无 UPDATE/DELETE**，记忆只累积、**不覆盖** | ✅ **我们已有**（I-3 分配不覆盖） |
| **2** | Agent 生成的事实同等权重 | ❌ 我们没有 |
| **3** | **Entity linking**：抽取实体、embedding、跨记忆链接，**用于提升检索** | ❌ **我们没有（这是差距）** |
| **4** | **Multi-signal retrieval**：语义 + BM25 + **实体匹配** 三路并行后融合 | ⚠️ **我们有三路，但没有"实体"这一路** |
| **5** | **Temporal Reasoning**：时间感知检索，对"当前状态/过去事件/未来计划"排对的时间实例 | ❌ 我们只有单一时间戳 |

### 2.2 最关键的工程数字

```
LoCoMo:       71.4 → 92.5     (+21)
LongMemEval:  67.8 → 94.4     (+27)
tokens:       7.0K / 6.8K
latency p50:  0.88s / 1.09s
检索预算:     top_200（单次调用，无 agentic 循环）
```

**← 这是本轮最重要的发现：**

> **Mem0 检索 top_200 条，但只注入 7.0K tokens。**
>
> **他们不是"少取几条"，是"多取再压缩"。**

**这直接解答了我 E-50 卡住的问题：**

| 我的困境（E-50） | Mem0 的解法 |
|---|---|
| 要召回 0.91 需要 200 条上下文 | 取 200 条，但压缩成 7K tokens |
| 条数爆炸 → 不可用 | **压缩后可用** |
| 结论："席位是硬约束" | **"席位不是硬约束，token 才是；而 token 可以压缩"** |

**→ 我 E-50 的结论"席位有限所以无解"是错的。真正有限的是 token，而 token 可压缩。**

## 三、Graphiti / Zep 的实现（README 明示）

### 3.1 双时态（bi-temporal）事实管理

> "Facts have validity windows. When information changes, old facts are **invalidated — not deleted**.
> Query what's true now, or what was true at any point in time."

**每条事实带两个时间：**
- `t_valid`：何时开始为真
- `t_invalid`：何时被取代（不是删除）

**→ 这解决了"旧信息还在但已过时"的问题，且不破坏"不遗忘"。**

**我们的差距**：只有单一时间戳，无法表达"这条曾经对，现在不对"。

### 3.2 Episodes（溯源）

> "Every entity and relationship traces back to the episodes (raw data) that produced it. Full lineage."

**→ 每条派生事实都能追回原始数据。**
**我们已经部分具备**（原文保留），但没有显式的 episode→fact 链路。

### 3.3 混合检索 + 图距离重排

> "Hybrid Retrieval: Combines semantic embeddings, keyword (BM25), and graph traversal"
> "Reranking search results using **graph distance**"

**→ 与我们三路一致，但多了"图距离重排"这一步。**

### 3.4 工程数字

```
延迟：sub-200ms at scale
去重阈值：duplicate 0.7，contradiction 0.8
```

## 四、汇总：他们领先的具体方法（可实验验证的）

| # | 方法 | 出处 | 为什么有效 | 我们缺不缺 |
|---|---|---|---|---|
| **M1** | **top-N 检索 + token 压缩** | Mem0（200条→7K tokens） | **绕开"席位 vs 召回"的零和** | ❌ **完全缺** |
| **M2** | **实体抽取 + 实体链接用于检索** | Mem0 | 实体是精确匹配的强信号 | ❌ 缺 |
| **M3** | **双时态失效（不删除）** | Graphiti | 处理"过时但仍需保留" | ❌ 缺 |
| **M4** | **Episode 溯源链** | Graphiti | 每个结论可追回原文 | ⚠️ 部分有 |
| **M5** | **图距离重排** | Graphiti | 关系远近作为排序信号 | ❌ 缺 |
| **M6** | **情绪标记（可追溯、按类别扩散）** | Nielson/Dunsmoor | 重要性由情绪闸门决定 | ❌ 缺 |

## 六、必须纠正我自己的一个错误

**E-50 我写的是："席位是硬约束，问题不在排序方式。"**

**这句错了。**

**真正的约束不是"席位"，是"token"。**
**而 token 可以压缩——Mem0 用 200 条原文压成 7K tokens。**

**→ E-50 的结论要修正为：**
> **"固定条数"是错的约束；正确做法是"多检索、再压缩到 token 预算"。**
