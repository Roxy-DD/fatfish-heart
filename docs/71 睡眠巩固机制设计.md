# 71 睡眠/巩固机制（Consolidation）设计

> 建立 2026-11-07。**本地记录，未写入思源。**

---

## 一、用户的核心定义

> "每一次模型自动觉得这个任务已经完成了、这个项目已经完成了等等，
>  感觉已经过了一个需要记忆点、需要进行整理回忆的节点之后，
>  它就会自动去触发这个记忆整理、回忆和遗忘的睡眠机制。"

**类比人的睡眠**：白天经历一堆事（短期记忆），睡觉时大脑自动：
1. **整理**：把零散的短期记忆归纳成长期记忆
2. **回忆/强化**：重放重要记忆，巩固它们
3. **遗忘**：清理过时、无用的

## 二、现状：缺这一环

| 机制 | 现有状态 | 对应人的 |
|---|---|---|
| 复盘（每轮判断该记什么） | ✅ 已有 | 白天"记下发生的事" |
| 矛盾处理（五类关系） | ✅ 已有 | 写入时"这条和旧的是不是一回事" |
| 熟练度（五通道记账） | ✅ 已有 | "用得多就顺" |
| **睡眠/巩固** | ❌ **缺失** | **睡觉时整理、回忆、遗忘** |

## 三、设计：睡眠机制是什么

### 3.1 触发：模型自主判断，不是定时

**关键**：和"复盘"一样，触发权在**模型**，不在规则。

模型在对话中，当它觉得"这个任务/项目告一段落了"时，**主动调用 `mem_sleep` 工具**做一次睡眠整理。

在"自主记忆准则"里加一条：
> 3. 睡眠整理（mem_sleep）：
>    当一个任务/项目告一段落、一个话题讨论完、一轮密集对话结束，
>    你觉得"是时候整理一下记忆了"，主动调用 mem_sleep。
>    这就像人睡觉时大脑自动巩固记忆。

### 3.2 睡眠做三件事

| 动作 | 含义 | 守红线的方式 |
|---|---|---|
| **整理** | 把最近几条相关碎片记忆，归纳成一条完整的"情景" | merge：旧的不删，打 superseded_by |
| **回忆/强化** | 重新激活本阶段关键记忆，强化通道计数 | channel.bump（只增不减） |
| **遗忘** | 把过时/被取代的记忆标记失效 | invalidate（打 invalid_at，不物理删） |

### 3.3 与现有机制的分工

```
每轮（实时）：
  复盘 → 判断"该不该记" → mem_add

节点（阶段性，模型自主触发）：
  睡眠 → 整理碎片 + 回忆强化 + 遗忘过时 → mem_sleep
```

**复盘是"记下来"，睡眠是"整理好"。**

## 四、实现方案

### 4.1 内核：加 `consolidate` 命令

```
输入：无（或指定时间范围）
流程：
  ① 扫描最近的记忆（如最近 N 条，或最近 M 分钟内新增的）
  ② 用 conflict.prepare_candidates 找"相关的候选对"
  ③ 打包给模型判断：哪些该 merge、哪些该 invalidate
  ④ 模型返回 → apply_verdict 落盘（打标记，不删）
```

### 4.2 插件：加 `mem_sleep` 工具

模型调用后 → 调内核 consolidate → 拿到"建议整理的候选" → 让模型判断 → 落盘。

### 4.3 分两步走

**第一步（最小可用）**：`mem_sleep` 工具 + 内核 consolidate，做"整理"（找重复/碎片让模型判 merge）。
**第二步（完整）**：加"回忆强化"（channel bump）和"遗忘"（invalidate）。

## 五、红线检查

| 红线 | 睡眠机制如何守 |
|---|---|
| R2 不遗忘 | 遗忘 = 打 invalid_at 标记，不物理删除 |
| R4 可塑性 | 整理 = merge（可追溯），失效可恢复 |
| R1 迁移 | 只操作 episodes 表已有字段，不加表 |
| R3 可重建 | 整理结果是从原文确定性重算的 |
