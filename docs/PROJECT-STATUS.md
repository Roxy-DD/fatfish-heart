## 一、这是什么

一套**跨模型、跨供应商、跨进程**都能接着记得的情景记忆系统。

核心主张：
- **一条记忆 = 一个情景**，记忆是纯数据（SQLite 单文件），不是模型内部状态
- **重要性 = 不记住的代价**（生存导向），不是频率
- **情绪是生理性自动的**，分 `affect_peak`（强度）与 `valence`（效价 [-1,1] 连续）

## 六、方法论纪律（踩坑换来的）

### 证据强度
```
代码执行的实际结果  >  文件系统/运行时状态  >  文本（人的描述）
```

### 三条硬规矩
1. **阈值必须双向标定**：已知正例 + 已知负例，只测一边必然偏
2. **看多个指标**：E-284 曾因只看饱和的 `recall@10` 而误判优化无效
3. **零误判优先于高召回**：漏判可后续补救，误杀则永久丢失

### 我的已知错误模式（需要程序性纪律对抗）
**看到异常数字就急着归因**。已连续四次：
- E-331：把两个 session 交替当成 log 重置
- E-332：把活跃会话当成僵尸会话
- E-341：把 24 次跨天注入当成设计失效
- E-342：用 10 分钟阈值硬切进程边界

**对抗方式**：
1. 时间序列先按实体（sid/进程）分段，再判定
2. 分段阈值本身要验证
3. 能直接跑单元实验的，不要绕道读日志推断
