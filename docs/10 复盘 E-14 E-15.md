## 二、我的三个实现 bug（必须记清）

### bug 1：`margin` 空操作（E-14）

回退逻辑：`pred[i] = a if tk[i,a] >= tk[i,b] else b`
但 `a = argmax(tk)`，所以 `tk[a] >= tk[b]` **恒真** → 永远选 a → **预测不变**。

**三个 delta 结果完全相同（0.8831），这是空操作的直接证据。** 我本该在跑之前从逻辑上发现。

### bug 2：`zc` / `zmax` 除以 sd，方向错误（E-14）

`(tk - mu) / sd`。
sd 小 的类 → z 值被放大 → **垄断 argmax**。
诊断：预测分布 `{5:95, 4:92, 3:45}`，真实分布 `{0:105, 2:99, 1:96}`。**完全错位。**

**除以 sd 奖励了"分布最窄"的类，而最窄的类恰恰是样本最不典型的那类。**

### bug 3：`rank` 设计必然退化（E-15）

我写的 `rank_scores` 取"该类最高百分位"，而**最大值永远 = 1.0**。
→ 所有类得分都是 1.0 → 并列 → argmax 取第一个 → 预测永远是 `0`。

结果：A 只得 0.3173（因为 A 含 0），B/C 全 0。**这是设计上的必然，不是数据问题。**

**三个 bug 有两个是"跑之前就能发现"的逻辑错误。** 这是本轮的元问题。

## 三、更重要的：为什么修正后仍然全部无效

即使 `margin2`（双向仲裁，8% 不一致率，有真实变化）和 `tk_cal`（正确的加法校正）都失败了：

| 方法 | 机制 | 结果 |
|---|---|---|
| `margin2` | tk 与 mx 分歧时按 gap 决定信谁 | **全部低于基线**（−12% ~ −25%） |
| `tk_cal` | 用类内均值拉平类偏置 | **单调变差**（c 越大越差） |
| `quota` | 按 1/√n 补偿小类 | 微增 +1.3%，不显著 |
| `rank` | 换排名尺度 | 设计缺陷，崩 |

### 3.1 三者的共同点

**它们都在事后修改 `argmax` 的打分。**

而 `base`（纯 topk3 argmax）已经是这个空间里的**局部最优**。

### 3.2 这说明什么

**跨任务干扰不是"打分有偏"造成的，所以任何重打分都治不好。**

`tk_cal` 单调变差是最强的证据：如果干扰来自"某些类的分数系统性偏高"，那么减去类内均值应该有帮助。**但减得越多越差** → 说明类内均值的差异**是真实信号，不是偏置**。

`margin2` 变差同理：tk 与 mx 的不一致（8%）里，**多数是 tk 对、mx 错**，仲裁反而引入错误。

**配额**微增 +1.3% 是唯一方向对的，但幅度说明密度不对称只占干扰的一小部分。

## 四、因此，对"6.89pp 干扰"的解释必须修改

### 4.1 原来的解释（E-13 复盘）

> 跨任务干扰 = 后学的任务抢走了先学任务的样本 → 需要"竞争性抑制/密度归一化"来解决

### 4.2 现在的证据推翻了这个解释

如果干扰是"类间的相对分数偏移"，重打分应该能修。**两轮都修不动。**

所以更可能的机制是：

> **干扰是"表征层"的，不是"打分层"的。**
>
> 1280 维 MobileNetV2 特征里，0/1/2 与 3/4/5 的某些样本本身就重叠。
> 当 10 个类同时存在时，一个"既像 2 又像 7"的样本，无论怎么打分都必须二选一。
> **oracle 之所以能到 0.95，是因为它作弊地排除了 7。**

### 4.3 这个解释的可检验推论

| 推论 | 检验方法 |
|---|---|
| 若干扰是表征层，**换更强的特征**应该显著改善 | 用别的编码器（CLIP / DINOv2 / 更强的 CNN） |
| 若干扰是表征层，**两两混淆矩阵**应该显示固定模式（如 4↔9、3↔5、7↔1） | 直接画 10×10 混淆矩阵 |
| 若干扰是表征层，**增加训练样本不会解决**，但**更好的类原型**会 | 试"每类只保留 1 个精心挑选的原型" |
| 若干扰是打分层，**oracle 与 base 的差距应该能被某种重打分弥合** | **已否证（两轮失败）** |

**最后一条已经被否证了。**

## 五、结论：这一轮的价值是"排除"

| 已被排除的解释 | 证据 |
|---|---|
| 干扰 = 类密度不对称 | quota 只回收 1.3% |
| 干扰 = 打分函数有偏 | tk_cal 单调变差 |
| 干扰 = tk 聚合不够鲁棒 | margin2 / topk5 / topk10 / topk20 都更差 |

**剩下的唯一解释：表征层的类间重叠。**

## 七、下一轮（E-16）：转向表征层

### 7.1 问题

> **6.89pp 的跨任务干扰，是否来自 1280 维 MobileNetV2 特征的类间重叠？**

### 7.2 设计

| 步骤 | 做什么 | 判据 |
|---|---|---|
| **① 混淆矩阵** | 学完 A→B→C 后，画 10×10 混淆矩阵 | 若错误集中在固定类对（4↔9, 3↔5, 7↔1），支持表征层假说 |
| **② 特征上限** | 用 sklearn 的最近质心/LDA/逻辑回归在**同一特征**上做 10 类分类（不涉及 Cosmos） | 若天花板也只有 ~0.95，说明特征本身就这水平 |
| **③ 换特征** | 试 2–3 个替代表征（像素 PCA、更强的预训练模型、或特征拼接） | 若换特征后 base 显著提升，则确认表征瓶颈 |
| **④ 原型精选** | 每类只用 1 个最优原型（medoid），去掉冗余子星 | 若接近 0.95，说明信息在，只是表达方式差 |

### 7.3 判据

| 项 | 判据 |
|---|---|
| 主判据 | macro > 0.90 |
| 若①②确认表征瓶颈 | **放弃"修算法"，改为"换表征"**，并明确记录"当前特征下 0.88 是上限" |

### 7.4 先说清楚的边界

- 若换特征需要下载新模型权重（几百 MB），要评估网络与时间
- 若结论是"0.88 是当前特征上限"，**这是一个合法结论，不是失败**
- **不能为了让数字好看而继续调参** —— 那会重犯 E-8/E-12 的错
