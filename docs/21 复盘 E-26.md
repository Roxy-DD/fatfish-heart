# 21 复盘 E-26：位移的损失到底来自哪里 —— 一条完美的因果链

> 记录 2026-10-25。**本地记录，未写入思源。**
> 目的：补 E-25 的缺陷（shift 会裁切图像），分离"定位敏感"与"信息丢失"。
> **结果：裁切贡献 = 0.0000，位移贡献 = −0.1575，质心对齐挽回 = +0.1575。**

## 一、数据

### 1.1 未对齐时的位移损失

| 测试域 | macro | 说明 |
|---|---|---|
| original | **0.9250** | 基线 |
| shift_crop(2,−2) | 0.7675 | 裁切 |
| **shift_pad(2,−2)** | **0.7675** | **不裁切** |
| shift_crop(4,0) | 0.4665 | 裁切 |
| shift_pad(4,0) | 0.4665 | 不裁切 |
| shift_pad(0,4) | 0.4945 | 不裁切 |

```
裁切造成的损失 = 0.7675 − 0.7675 = +0.0000   ← 完全为零
纯位移的损失   = 0.7675 − 0.9250 = −0.1575
```

**裁切贡献为 0。E-25 那个 −16.5pp 全部是"纯位移"，不是"信息丢失"。**

### 1.2 质心对齐后

| 测试域（已对齐） | macro |
|---|---|
| original | **0.9345** |
| shift_crop(2,−2) | **0.9345** |
| shift_pad(2,−2) | **0.9345** |
| shift_crop(4,0) | 0.9325 |
| shift_pad(4,0) | 0.9325 |
| shift_pad(0,4) | 0.9330 |

```
质心对齐挽回 = +0.1575   （正好等于未对齐时的全部位移损失）
```

**这是一个完整的因果闭环：**

```
诊断：位移导致 −15.75pp
其中：裁切 0.00pp，定位错位 15.75pp
改法：质心对齐
验证：对齐后，位移的影响降到 0.00（2px）/ −0.20pp（4px）
```

**修复后的性能还更高**（0.9250 → 0.9345，+0.95pp），因为对齐本身让同类样本更一致。

## 二、一个必须指出的细节：为什么 crop 和 pad 完全一样

`shift_crop` 和 `shift_pad` 结果**一模一样（都是 0.7675）**。

**原因：MNIST 数字本来就在 28×28 里留了边距**（原始数据有 4px padding，数字本身在中间 20×20 附近）。平移 2px 不会裁掉任何笔画。

**这恰好证明了：平移 2px 时，"裁切"这个担心是多余的。**

但 4px 平移时结果也完全一样（0.4665）——**说明即使 4px 也没裁到笔画。**

**结论：我 E-25 里担心的"裁切缺陷"，实际不存在。** 那个 −16.5pp 是干净的"纯位移损失"。

**这是好消息**：E-25 的结论（形状原型、位置模板）**不需要修正，反而被加固了**。

## 三、第三个实验：显式加位置特征 —— 失败

| w（位置特征权重） | original | shift_pad | 位移损失 |
|---|---|---|---|
| 0.00 | 0.9250 | 0.7675 | −0.1575 |
| 0.05 | 0.9260 | 0.7680 | −0.1580 |
| 0.10 | 0.9260 | 0.7680 | −0.1580 |
| 0.20 | 0.9260 | 0.7690 | −0.1570 |

**完全无效。**

**为什么**：位置特征的范围是 y∈[0.481, 0.518]、x∈[0.482, 0.518]——**只有 ±2% 的波动**。

平移 2px 在 28×28 里是 7% 的位移，但**质心位置只变了 2%**，因为数字本身有笔画厚度。

**→ 用"质心"做位置代理，分辨率不够。**

而且**加位置特征本身不解决错位问题**——错位发生在"分块统计"那一层，不在"特征拼接"那一层。

## 四、这一组的真正价值

### 4.1 一条完整的方法论示例

这是整个项目里**第一次做到"诊断 → 定位 → 修复 → 验证"四步闭环**：

| 步骤 | 做了什么 | 结果 |
|---|---|---|
| 诊断 | E-25 发现位移掉 16.5pp | −16.5pp |
| **排除干扰** | E-26 补 crop vs pad 对照 | 裁切 0.00pp |
| **定位** | 确认是"绝对网格位置" | 纯位移 −15.75pp |
| **修复** | 质心对齐 | 挽回 +15.75pp |
| **验证** | 对齐后位移影响 | 2px: 0.00pp；4px: −0.20pp |

### 4.2 得到一个可迁移的结论

> **同一类东西，如果"摆放位置"会变，那么必须先对齐再提特征。**
>
> **否则你学到的是"位置模板"，不是"形状原型"。**

**这个结论不止适用于手写数字**：
- 人脸识别要眼睛对齐
- 指纹识别要先找到核心点
- 物体识别要 bounding box 归一化
- **语音要先做时间对齐**

**这是"规律只出现在现实里"的一个实例**：所有真实世界的识别系统都做对齐，因为**世界上的东西不会每次都摆在同一个位置**。
