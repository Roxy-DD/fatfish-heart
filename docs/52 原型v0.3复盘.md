## 二、失败的部分：链式展开走错了方向

### 2.1 实际发生什么

**加 `--expand` 后，多出两条"跳"记录：**

| 跳数 | 内容 | 问题 |
|---|---|---|
| **第 1 跳** | **老板说项目千万别搞错，要出大事** | ❌ **完全无关** |
| **第 2 跳** | **我电脑密码是8848** | ❌ **完全无关** |

**而"童年夕阳"本来就已经在第 2 名，所以展开没有带来任何新东西。**

### 2.2 为什么错

**我的展开逻辑里有一项是"共同话题"，而 `topic` 里有"技术""工作"这种粗类别。**

```
seed(夕阳) topic = ["场景"]
```

**但展开时，我还混入了"重要性加成"和"情绪共振"：**
- 老板那条 arousal=0.33、valence=−1.00
- 密码那条 importance=0.90

**我的 `_expand_from` 里"情绪共振"只判断 `same_sign = v*seed.valence>0`，
seed 的 valence 是 0.00 → `v*0 > 0` 为假，理论上不该命中。**

**实际命中的原因是第三条："共同话题"**——但我 seed 的 topic 是"场景"，
老板那条是"工作"，密码那条是"技术"，**不该匹配。**

**→ 说明代码里有我没发现的通路。必须查。**

### 2.3 必须查清的

**怀疑点：`_search_flat` 的结果被当成了 seed，而 seed 里包含了 score 0.774 的"接口参数"那条。
从那条展开时，它的 topic=["技术"] → 匹配到密码条 → 于是密码被拉进来。**

**也就是说：我从"最弱的相关结果"往上展开了，而不是从"最强的 seed"。**

## 三、这个失败暴露的设计问题

**用户描述的链式展开是：**
> 看到夕阳 → 想起"我也在哪见过这样的夕阳" → **顺着那个夕阳** → 想起小时候在哪看的夕阳 → 小时候的事

**关键：链条是"沿着情景的相似性"走的，不是"沿着任何一条相关记录"走的。**

**我的实现错在：**
| 我的做法 | 应该的做法 |
|---|---|
| 从 top-1 展开 | 从 top-1 展开 ✅（这部分对） |
| 展开时混入"重要性加成" | **不该混入**——重要性是"是否值得记"，不是"是否相关" |
| 用粗 topic 类匹配 | 应该用**具体场景词**（夕阳、橘红色） |
| 跳数没有收敛条件 | 应该**只在相似度足够高时**才继续跳 |

---

## 四、修正方案（下一版）

### 4.1 展开只沿两条路

```
路 A：情景相似（向量相似度 > 阈值，且比 seed 低但足够高）
路 B：情绪共振（valence 同号 且 |arousal 差| < 0.2，且两者 arousal 都 > 0.2）
```

**移除"重要性加成"和"粗 topic"这两项。**

### 4.2 加收敛条件

```
若候选相似度 < seed 相似度 * 0.6 → 停止（防止越跳越远）
每跳最多 1-2 条
总条数上限 = top + 2*hops
```

### 4.3 加"场景词"这一层

**用户说的"夕阳"是具体场景词，不是"场景"这个类。**
**需要从文本里抽具体名词（夕阳、橘红色、院子），而不是归类。**
