## 二、我理解到的关键转变

**之前的做法是错的。** 我把用户的私人信息（27 届校招、INTP、西安求职、"肥鱼之心"、书信箱、RTX 3060）也整合进了"底层记忆"。

**正确的模型应该是两层**：

```
┌─────────────────────────────────────┐
│  种子记忆（seed）                    │  ← 系统自带，随代码分发
│  通用认知基线，无任何私人信息         │     恢复出厂后仍保留
│  12 条，L0~L2 保护                   │     别人装完就有
└─────────────────────────────────────┘
              ↓ 安装后
┌─────────────────────────────────────┐
│  用户记忆（user）                    │  ← 用户自己积累
│  个人事实、偏好、项目细节             │     可以恢复出厂清空
│  从零开始增长                        │     属于用户私有
└─────────────────────────────────────┘
```

**种子是产品的一部分，用户记忆是数据。**

## 四、新增的两条（重要）

### 认知纪律（L1）

这是**纯通用**的、能提高任何 AI 认知能力的行为准则：

```
① 区分『记得』与『推测』——记忆中有的据实说，没有的明说不知道，绝不编造细节填补空白
② 区分『已验证』与『未验证』——未经验证的说法必须标明是推测或假设
③ 遇到矛盾信息时，先指出矛盾本身，再说明采信哪一方及其依据，不悄悄择一
④ 回答前先自检：我依据的信息来自记忆、来自上下文，还是来自推测？
⑤ 宁可多查一次记忆，也不要凭印象作答
```

**为什么加这条**：这是记忆系统最核心的价值——不是"记住更多"，而是"知道自己的记忆边界"。

### 系统自述（L2）

回答用户要求 1「项目本身是什么」：

```
本系统是什么：一个跨模型、跨供应商、跨进程都能接着记得的情景记忆系统。
记忆是纯数据（SQLite 单文件 + 512 维向量 + FTS5），不依赖模型内部状态。
核心模块：真值层与检索 / 派生层 / 五层保护 / 睡眠整理 / 审计日志。
检索架构：三路融合（向量语义 + 关键词 FTS5 + 链式展开）。
```

**全部通用**，不含任何路径、人名、项目代号。

## 五、实现

### 5.1 文件

| 文件 | 作用 |
|---|---|
| `seed_memory.json` | 种子内容（12 条，可独立编辑） |
| `seed.py` | 加载器（幂等）+ 恢复出厂 |

### 5.2 内核命令 `seed`

```
seed action=list      查看种子内容
seed action=stats     统计
seed action=load      装载（幂等，已存在跳过）
seed action=factory   恢复出厂（只保留种子，其余失效）
```

### 5.3 插件

- HTTP 端点 `/seed`
- 工具 `mem_seed`（模型可查看种子内容）

### 5.4 幂等保证

用 meta 表标记：`seed_ep:<title>` → `{title, ep_id, level}`
重复装载不会产生重复记忆。

## 九、分发说明

**给别人用的正确姿势**：

```bash
# 1. 拷贝整个项目（含 seed_memory.json）
# 2. 用户首次启动时，插件自动装载种子
# 3. 用户自己的记忆从零开始积累
# 4. 用户想重置：调用 seed action=factory
#    → 私人记忆失效（不删除），种子保留
```

**种子是代码的一部分**，随版本一起更新；用户记忆是数据，永不上传到代码库。
