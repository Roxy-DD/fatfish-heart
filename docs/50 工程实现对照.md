## 一、"一条记忆 = 一个情景" → 事件切分（Event Segmentation Theory）

### 1.1 ES-Mem（arXiv 2601.07582）

**它说的两个痛点，正是我犯的错：**

> ① "**rigid memory granularity often disrupts semantic integrity**,
> resulting in fragmented and incoherent memory units"
> （固定的记忆粒度破坏了语义完整性，导致记忆单元碎片化、不连贯）
>
> ② "prevalent **flat retrieval** paradigms rely solely on surface-level semantic similarity,
> **neglecting the structural cues of discourse**"
> （扁平检索只靠表面语义相似，忽略了话语的结构线索）

**→ 第①条说的就是我：我一直按"一条事实"存，把情景切碎了。**

**它的做法：**
- **动态事件切分**：把长期交互切成"语义连贯、有明确边界"的事件
- **层级记忆**：多层记忆，用"边界语义"作为锚点定位具体情景

### 1.2 HingeMem（arXiv 2604.06845）—— 切分规则非常具体

**这是我最需要的那条：切分依据是四个要素：**

> "boundary-triggered hyperedges over four elements:
> **person, time, location, and topic**"
> （以 **人、时间、地点、话题** 四要素的边界触发超边）
>
> "**When any such element changes, HingeMem draws a boundary and writes the current segment**"
> （**任一要素发生变化，就画边界，写入当前片段**）

**→ 切分规则极其朴素：人、时间、地点、话题，任一变了就切一刀。**

**而且它做了"查多少"的自适应：**
> (a) what to retrieve: 按元素索引路由
> (b) **how much to retrieve: 根据估计的查询类型控制检索深度**

**实测数字（LOCOMO）：**
> 相对提升约 **20%**，且问答 token 成本比 HippoRAG2 **降低 68%**

**→ "按查询类型决定查多少"这一条，正是我 E-50 得出的"分层"结论，
但它是靠**查询类型路由**实现的，不是靠固定的 k 或阈值。这是我没想到的角度。**

## 二、"情绪是连续维度、生理性" → Valence-Arousal + GoEmotions

### 2.1 维度模型（效价-唤醒）

**我在 arXiv 上查到的情绪识别论文，主流都是 valence-arousal 二维空间：**

| 论文 | 做法 |
|---|---|
| Audio-Visual Fusion for Emotion Recognition in the Valence-Arousal Space | 跨注意力融合 |
| Emotion as a Distribution: Joint Valence-Arousal Probability Learning | **输出概率分布，不是单一值** |
| Recursive Joint Cross-Modal Attention | 多模态融合 |

**→ 行业落地做法：情绪不是"7 种分类"，是"效价（好/坏）+ 唤醒（强/弱）"二维连续值。**

**这正好对应你说的：**
> "情绪……就像小脑，它自动处理了……你难过的时候是生理反应"

**生理反应就是连续强度，不是离散标签。**

### 2.2 GoEmotions（Google，58k 条，27 类 + Neutral）

**若需要细分类，这是标准数据集：**
- 5.8 万条人工标注
- **27 种情绪 + 中性**
- BERT-base 微调 F1：**0.46（27 类）/ 0.64（Ekman 6 类）**

**→ 注意这个数字：27 类 F1 只有 0.46。**
**说明"细粒度情绪识别"在文本上并不精确。这印证了我的担心。**

**→ 所以更实用的可能是二维（效价+唤醒），而不是 27 类。**

## 三、我的结论：该怎么做

### 3.1 存储结构要改（从"事实"改成"情景"）

**现在的结构（错的）：**
```
一条记忆 = { text, vector, timestamp }
```

**应该改成（情景）：**
```
一条情景 = {
  seg_id,
  四要素: { person, time, location, topic },   ← 切分依据
  边界标记: 哪个要素变了,
  骨架: 发生了什么,
  氛围: 环境质感,
  情绪: { valence, arousal },                  ← 二维连续值
  原文: 完整保留（不切碎，红线）
}
```

### 3.2 情绪怎么做

| 方案 | 可行性 | 我的判断 |
|---|---|---|
| 27 类分类 | F1 仅 0.46 | ❌ 太不准 |
| **效价+唤醒 二维** | 连续值，可回归 | ✅ **优先** |
| 规则 + 关键词（"千万别"、"要出大事"） | 简单可靠 | ✅ **先做这个** |
| 显式标记（用户说"记住这条"） | 100% 准确 | ✅ **必须有** |

**→ 顺序：先做"显式标记 + 规则"，再叠加"二维情绪值"。**

### 3.3 检索怎么做

**HingeMem 的思路值得抄：**
```
1. 按查询类型路由（问"人"就查人索引，问"什么时候"查时间）
2. 按查询类型决定深度（不是固定 k）
```

**这正是我 E-50 想解决但没解决的那一条。**
