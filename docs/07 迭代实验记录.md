### 2.1 三条读数

**① topk3 是最优，但 topk 越大越差（topk20 反降）。**
k=3 是甜蜜点。k 变大后，"类内 top-k 均值"开始稀释掉真实的最近邻信号。

**② `prior` 是双刃：小 beta 微增，大 beta 崩盘。**
beta=0.02/0.05 有微小的 C 提升（0.8600→0.8933），但 A 几乎不动。
beta=0.1 起 A/B 急剧下降，beta=0.4 时 B 掉到 0.0567。
**说明"惩罚大类"这个方向在大 beta 下会摧毁大类本身。**

**③ zscore 彻底失败，即使加了候选筛选。**
原因：候选筛选用 max，再在候选内比 zscore，两个尺度混用。大类内部方差小、z 值高，小类反而被压制。

### 2.2 ⚠ 这里有个必须先澄清的问题

E-9 的 `max` 基线是 **0.8467**，而 E-1 同配置是 **0.6767**。

**差异不是噪声，是检索结构不同**（E-10 专门查了这个）。

## 三、E-10：层级递归 vs 平坦（决定性）

| 检索方式 | A | B | C | macro |
|---|---|---|---|---|
| **hier_recursive（原实现）** | **0.6767** | 0.8700 | 0.8600 | 0.8022 |
| **flat_root_only（411 根）** | **0.6767** | 0.8700 | 0.8600 | 0.8022 |
| **flat_all_stars（1428）** | **0.8467** | 0.9067 | 0.8400 | **0.8644** |
| **topk3_all_stars** | **0.8933** | 0.9200 | 0.8567 | **0.8900** |
| topk3_root_only | 0.5033 | 0.8567 | 0.9000 | 0.7533 |
| topk5_all_stars | 0.8933 | 0.8933 | 0.8400 | 0.8756 |

### 3.1 两个硬结论

**结论 1：`hier_recursive` 与 `flat_root_only` 完全同分（0.6767）。**

→ **在层级检索里，1017 颗子星从来没被用上。**

机制：`perceive()` 递归的条件是「root 的 sim > T 且该 root 有子星」。
- 若 root 命中**同一概念** → 进子池，但子星与父星相似度均值 **0.9148**，几乎是复制品 → 结果不变
- 若 root 命中**错误概念** → 进的是**错误子池** → 锁死，无法纠正

**两条路都等于"子星没起作用"。**

**结论 2：同样的星，平坦检索 +17.0pp（A），+6.2pp（macro）。**

→ **层级结构是纯粹的负担，没有任何收益。**

这是对**设计意图第 5 条（质量计数 → 分裂 → 层级）**的直接否证。

### 3.2 子星的真实构成

```
类目数 83，平均子星数 9.1，子星总数 1017
子星 vs 父星 相似度: 均值 0.9148, min 0.7529, max 0.9758
```

子星不是"更细的概念"，是**同标签向量的累积副本**。

## 四、E-11：17pp 到底来自"内容"还是"数量"（因果分离）

这是本轮最关键的一步。因为 `flat_all(1428)` 与 `flat_root(411)` **信息量不同**，不能直接比"检索方式"。

设计四组对照：

| 组 | 向量数 | 内容 |
|---|---|---|
| A `root_only` | 411 | 只用根星 |
| B `all_stars` | 1428 | 根星 + **真实子星** |
| C `root+随机复制` | 1428 | 根星 + 随机复制根星（**只增数量，不加信息**） |
| D `root+噪声扰动` | 1428 | 根星 + 加噪扰动副本（**数量+噪声，不加信息**） |

### 4.1 结果（macro）

| 设置 | top-1 | top-3 | top-5 |
|---|---|---|---|
| root_only (411) | 0.8022 | 0.7533 | 0.7033 |
| all_stars (1428) | **0.8644** | **0.8900** | **0.8756** |
| root+随机复制 (1428) | 0.8022 | 0.8067 | 0.8267 |
| root+噪声扰动 (1428) | 0.8022 | 0.7533 | 0.6311 |

### 4.2 判定

```
真实子星增益  +0.1367
随机复制增益  +0.0534
噪声增益      +0.0000
```

**★ 真实子星提供了额外信息，不只是数量。**

三个读法：

**① 数量有贡献，但只有一部分。**
随机复制也涨了 +5.34pp，说明"每个概念拥有更多候选票"确实有效（top-k 聚合让小类不吃亏）。

**② 内容贡献更大。**
真实子星 +13.67pp vs 随机复制 +5.34pp，**多出 8.33pp 来自子星的真实内容**。

**③ 噪声直接归零。**
加噪版本完全无增益（top-1 0.8022，与 root_only 相同）。
→ 说明**子星的增量信息来自"真实样本多样性"，不是"数量"本身**。噪声只会污染。

### 4.3 这推翻了我上一轮的猜测

我在 E-10 后猜"子星可能是冗余的复制品"。**E-11 否证了这个猜测。**

子星与父星余弦 0.9148 看起来很近，但在 1280 维里，**0.9148 的差异包含真实的类内变异**（不同书写风格）。
复制和噪声都模拟不了这种变异，所以增益消失。

**→ 设计意图第 5 条（分裂）本身是对的，错的是"把它组织成层级"。**

## 六、还差 0.67pp，下一步试什么

**剩余失败模式（学完 C 后，任务 A 的 A=0.8933）**：还差 0.67pp 才到 0.90。

按性价比：

| 优先级 | 试什么 | 理由 |
|---|---|---|
| **P0** | **top-3 与 top-1 的混合**（如 max(m, topk3) 或加权） | top-1 在 C 上更好（0.8400），top-3 在 A/B 更好。混可能补上 |
| **P0** | **每类保底配额（quota）** | 直接治"密度不对称"（A:29 vs C:226 根） |
| P1 | **用真实子星，但`dream()`时合并进父星而非保留为层级** | 保留信息，去掉层级负担 |
| P1 | 多种子重复（当前只有 seed=0） | 0.67pp 可能落在种子方差内，**必须先确认这不是噪声** |
| P2 | 双阈值正式优化（T_alloc × T_merge 网格） | E-7 只扫了 T_merge |

**注意**：0.67pp 很小。**在单种子下不能宣称"接近达成"**，必须先跑多种子确认 0.8933 的稳定性。

## 七、必须记下的方法论教训

| 教训 | 来源 |
|---|---|
| **改动学习器会让基线不可比** | E-8（0.8533）vs E-1（0.6767），浪费了一轮 |
| **参数必须先检查量级** | E-8 `density` 用 alpha=0.5，而 log1p(n)≈4.9，理论值应 ~0.01 |
| **跨类分数必须先归一化才能比较** | E-8 `zscore` 直接跨类比，全崩 |
| **"信息量不同"不能直接当"方法不同"比较** | E-10→E-11，必须加复制/噪声对照组 |
| **我猜错了一次** | 猜"子星是冗余"，E-11 否证。**记下来，这个猜测错了** |
