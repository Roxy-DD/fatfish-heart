# 搜索工具现状与增强方案（2026-11-20）

## 一、最重要的结论（实测）

**内置 `web_search` 现在是坏的** —— 本轮实测调用返回：

```
DeepSeek API error (HTTP 402): Insufficient Balance
请求打到 https://api.deepseek.com/v1/tools/search
```

内置搜索走的是 DeepSeek 模型的搜索端点，**账户余额不足时直接失效**。

**而 MCP 的 Exa 搜索实测可用**（`mcp__exa-search__web_search_exa` 多次调用成功）。

→ **现在就该把联网搜索主路径切到 Exa。**

一个矛盾现象：`mcp_connector_status` 显示 Exa "连接异常/timeout"，
但实际工具调用全部成功。**以实测为准，健康状态是误报**。

## 三、Exa 能力（官方核实）

**Exa 3.0（2026-10 发布）**：语义搜索（按意义非关键词）、100B+ 页面索引、
Dynamic Highlights（比全文少 95% token）。官方称在其测的所有 benchmark 排第一。

**价格**：免费层每月 $10 credit + $10 注册赠送，免卡；
MCP keyless 模式无需 key 即可搜索/抓取（有限速），但 `agent_run` 必须 key。

**关键**：当前连接的 URL 是
`https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa,web_search_advanced_exa`
—— **缺 `agent_run`**，所以深度研究功能没开。

## 四、值得加装的工具（按"现在就能做"排序）

### 方案 A（首选，零安装）：升级 Exa 到完整能力
- 在 connector 的 URL tools 参数补上 `agent_run`，走 OAuth 或加 API key
- 提升：解锁多步深度研究、结构化输出、列表构建
- 内置搜索挂了，Exa 是现成替代

### 方案 B（一键）：加装 Tavily 作第二信源
- `mcp_connector_catalog(keyword="Tavily")` → `mcp_connector_connect`
- 免费 1000 credits/月，OAuth 一键
- 提升：交叉验证，减少单一来源偏差

### 方案 C（中文/抓取增强，二选一）
- **博查 bocha-search**：中文网页/AI 搜索，中文资料覆盖更好
- **Firecrawl**（`https://mcp.firecrawl.dev/v2/mcp`）：JS 渲染页面、文档站抓取最强，keyless 起步

其他可选：Jina AI Reader（任意 URL 转干净 Markdown）、SearXNG（自建、隐私）、Brave（独立索引，需 key）。

## 五点五、实测：Tavily keyless 在当前 DSH 连接器里装不上（2026-11-20）

我尝试用 `mcp_connector_configure` 配 Tavily 的 keyless 端点
（`https://mcp.tavily.com/mcp/`，文档说 Search/Extract 无需 key），
**结果 HTTP 401，连接未保存**。

原因：Tavily 文档说的 keyless 是"工具调用层面无需 key"，
但 **DSH 连接器在 initialize 握手阶段就要求鉴权**，keyless 过不了这一关。

**结论**：方案 B（Tavily）在当前架构下必须走两条路之一：
1. **OAuth**：市场连接 `tavily-search`，`mcp_connector_connect` 弹浏览器登录 Tavily 账号
2. **API key**：去 https://app.tavily.com 拿 key，URL 加 `?tavilyApiKey=<key>`

两条都需要用户本人操作，AI 无法代劳（涉及账号登录/密钥）。

## 五、我的建议

**立刻做**：把搜索主路径切到 Exa（已可用），别再用内置 `web_search`。

**要增强**：
1. 先给 Exa 补 `agent_run`（零成本，解锁深度研究）
2. 再装 Tavily 作第二信源（交叉验证）
3. 如果中文资料多，加博查

**不建议**：SearXNG 自建（维护成本高）、Brave（要信用卡）。

## 五点六、权威核实：当前实际注册的搜索工具（cordis Tool.listTools）

用 `cordis_inspect_query(host, Tool, listTools)` 拿到当前 Agent 实际能调用的全部工具，
grep 后确认搜索类只有这些：

| 工具 | 来源 |
|---|---|
| `mcp__exa-search__web_search_exa` | Exa MCP |
| `mcp__exa-search__web_search_advanced_exa` | Exa MCP |
| `mcp__exa-search__web_fetch_exa` | Exa MCP |
| `web_search` / `web_fetch` | DSH 内置（402 挂了）|
| `mcp__itsaplan__search_issues*` | 业务搜索，非全网 |
| `mem_search` / `mcp_connector_tool_search` | 记忆/连接器检索，非全网 |

**结论确认**：`agent_run` **确实没有注册**（grep 无匹配，只有 itsaplan 的
`list_agent_runs` 是同名干扰项）。所以 Exa 深度研究功能当前不可用，
要启用必须改连接器配置 + 授权。
